# AI-aamuraportti - 2026-11-05

- Microsoft julkaisi Agent Frameworkille asennettavat "builder"-skillit .NET:lle ja Pythonille, joten Claude Code tai Copilot saa Microsoftin ylläpitämät ohjeet Agent Framework -sovellusten rakentamiseen (`npx skills add microsoft/agent-framework --skill agent-framework-builder-dotnet`).
- GitHub Copilot on nyt natiivi agenttivaihtoehto JetBrains AI Assistantin agenttivalitsimessa (4.11.), mikä täydentää eilen raportoitua JetBrains Air -tukea.

## Kehitystyökalut ja agentit

**GitHub Copilot natiivina agenttina JetBrains AI Assistantissa** (julkaistu 4.11.) `[Kokeile]` - Microsoft for Java Developers -blogin päivitetyn kirjoituksen mukaan GitHub Copilot on nyt ensiluokkainen, natiivi vaihtoehto JetBrains AI Assistantin agenttivalitsimessa. Kirjoituksen aiemmin kuvaama integraatiotapa on merkitty vanhentuneeksi. Kyse on eri asiasta kuin eilen raportoitu JetBrains Air -tuki: tämä toimii tavallisissa JetBrains-IDE:issä AI Assistantin kautta. [Microsoft DevBlogs](https://devblogs.microsoft.com/java/access-github-copilot-in-jetbrains-github-copilot-is-now-a-native-agent-in-jetbrains-ai-assistant/)
*Miksi tärkeä / mitä kokeilla:* Riderin käyttäjät voivat valita Copilotin agentiksi suoraan AI Assistantin agenttivalitsimesta ilman Airia. Kokeilkaa samaa .NET-refaktorointitehtävää Copilot- ja Claude Agent -valinnoilla ja vertailkaa tuloksia.

**Intelligent Terminal 0.3** (julkaistu 4.11.) `[Seuraa]` - Microsoftin kokeellinen, avoimen lähdekoodin Windows Terminal -haara, johon agentit on rakennettu sisään. Versio 0.3 keskittyy välilehtien ja agenttien hallintaan. Command Paletteen kirjoitettu `?` ja sen perään annettu prompti käynnistää agentin taustavälilehteen aktiivisen paneelin kontekstilla. `/agent` valitsee välilehden agentin, ja hallintapaneeli listaa aktiiviset agentit ja aiemmat sessiot. Oletusagentti on Copilot, mutta myös muut ACP-yhteensopivat CLI:t toimivat. Version 0.3 tarkkaa muutoslistaa ei saatu hakutuloksista. [Intelligent Terminal](https://developer.microsoft.com/en-us/windows/intelligent-terminal) · [Microsoft DevBlogs](https://devblogs.microsoft.com/)
*Miksi tärkeä / mitä kokeilla:* Windows-kehittäjille tämä on kevyt tapa ajaa useita CLI-agentteja rinnakkain välilehdissä. Seuratkaa, toimiiko Claude Code ACP-sovittimen kautta ennen kuin otatte sen laajemmin käyttöön.

**Codex CLI 0.168.0-alpha.3** (julkaistu 5.11.) `[Seuraa]` - Eilen raportoidun alpha.1:n jälkeen npm:ään on tullut jo alpha.3. Viimeisin vakaa versio on yhä 0.166.0 (29.10.), eikä julkaisumuistiinpanoja ole. Lisäksi GitHub-issue #59487 (4.11.) raportoi viikkokiintiön pudonneen noin 20 %:sta nollaan 10 minuutissa. Kyse on yksittäisestä raportista, eikä OpenAI ole vahvistanut vikaa. [npm @openai/codex](https://www.npmjs.com/package/@openai/codex) · [openai/codex #59487](https://github.com/openai/codex/issues/59487)
*Miksi tärkeä / mitä kokeilla:* Pysykää versiossa 0.166.0. Jos Codexin kiintiö hupenee selittämättömästi, tarkistakaa käyttö `/status`-komennolla ja raportoikaa `/feedback`-komennolla.

## Pluginit, skillit ja MCP

**Microsoft Agent Framework -builder-skillit .NET:lle ja Pythonille** (PR 23.10., uutisoitu 4.11.) `[Kokeile]` - Microsoft julkaisi kaksi koodausagenteille tarkoitettua skilliä: `agent-framework-builder-dotnet` (C#) ja `agent-framework-builder-python`. Ne antavat Claude Codelle, Copilotille, Cursorille ja Codexille Microsoftin ylläpitämät ohjeet Agent Framework -sovellusten rakentamiseen, muokkaamiseen, katselmointiin, evaluointiin ja hostaamiseen. Viiteosioissa käsitellään workflow-rakennetta, orkestrointia, validointia, observabilitya, hostausta ja deklaratiivisia YAML-määrityksiä. Nämä ovat eri asia kuin Agent Frameworkin ajonaikaiset Agent Skills -paketit. .NET-skilli ei ole vielä tagatussa julkaisussa, joten se asennetaan `@main`-viittauksella. [Microsoft Learn](https://learn.microsoft.com/en-us/agent-framework/get-started/build-with-coding-agents) · [SKILL.md](https://github.com/microsoft/agent-framework/blob/main/skills/agent-framework-builder-dotnet/SKILL.md) · [PR #9651](https://github.com/microsoft/agent-framework/pull/9651)
*Miksi tärkeä / mitä kokeilla:* Lue ensin SKILL.md ja asenna sitten .NET-repoon `npx skills add microsoft/agent-framework --skill agent-framework-builder-dotnet` tai `gh skill install microsoft/agent-framework agent-framework-builder-dotnet@main`. Testaa skilliä pyytämällä Claude Codea rakentamaan Azure-hostattu Agent Framework -workflow.

## Toimintatavat ja arkkitehtuuripatternit

**Qodo: koodikatselmointiagentin rakentaminen ja evaluointi** (julkaistu 3.11.) `[Kokeile]` - Käytännön ohje siihen, milloin oma AI-katselmointiagentti kannattaa rakentaa ja milloin ostaa alusta. Evaluointiosion ydin on pitää yllä labeloitua PR-joukkoa ja ajaa se uudelleen aina, kun prompti, malli tai löydössuodatin muuttuu. Tuotannossa mitataan, kuinka suuren osan agentin löydöksistä kehittäjät hyväksyvät tai korjaavat. [Qodo-blogi](https://www.qodo.ai/blog/build-vs-buy-code-review-agent/)
*Miksi tärkeä / mitä kokeilla:* Jos ajatte Claude Code -katselmointia ADO:n PR-pipelinessa, kerätkää 20–30 historiallista PR:ää, joiden oikeat löydökset tiedetään, ja ajakaa ne regressiotestinä aina ennen kuin vaihdatte mallia tai promptia.

**Suunnitteludokumentti katselmointiagentin kontekstiksi** (julkaistu 4.11.) `[Kokeile]` - Kokeilukirjoituksessa agentti katselmoi PR:iä niin, että sen kontekstiin annettiin myös muutoksen suunnitteludokumentti. Kirjoittajan johtopäätös on, että kontekstin laatu ratkaisee löydösten osuvuuden enemmän kuin mallin valinta: agentti tunnistaa poikkeamat aiotusta toteutuksesta, ei pelkkiä tyylivirheitä. Lähde on yhteisön blogikirjoitus, ei mitattu tutkimus. [DEV Community](https://dev.to/aroua_kaboubi_82466ca9a52/ai-agents-as-code-reviewers-give-them-the-design-doc-1ib)
*Miksi tärkeä / mitä kokeilla:* Linkatkaa ADO-work itemin kuvaus tai spec-tiedosto katselmointipromptiin, esimerkiksi `claude -p "Katselmoi diff suhteessa specs/<feature>.md"`, ja vertailkaa löydöksiä nykyiseen pelkkää diffiä katselmoivaan ajoon.

## Uudet mallit

**Kimi K3.1 Pro: avoimet painot julkaistu** (julkaistu 4.11.) `[Seuraa]` - Edelliseen raporttiin verrattuna painot ovat nyt oikeasti julkaistu: ne ovat Hugging Facessa repossa `moonshotai/Kimi-K3.1-Pro`. Kokoa on noin 1,56 TB 96 shardissa, painot ovat MXFP4-muodossa ja aktivaatiot MXFP8:na. Malli on MoE, jossa on 2,8T parametria (104B aktiivisena) ja noin 1M tokenin konteksti. Lähteet ovat eri mieltä lisenssistä: osa kuvaa sitä MIT-tyyppiseksi, osa custom-lisenssiksi, jossa on liikevaihtoraja (K3-lisenssin raja on 20 M$ kuukausiliikevaihto tai 100 M kuukausikäyttäjää). Ollama, Nebius ja Databricks ilmoittivat tuesta. Itse ajaminen vaatii luokkaa 8× B300 -palvelimen. [Superpower Daily](https://superpowerdaily.com/posts/moonshot-publishes-kimi-k3-1-pro-weights-opening-a-self-hosted-route-for-coding-agents) · [OrcaRouter: lisenssi ja kustannukset](https://www.orcarouter.ai/blog/kimi-k3-1-pro-weights-released-self-hosting-cost)
*Miksi tärkeä / mitä kokeilla:* Lukekaa repon LICENSE-tiedosto ennen kaupallista käyttöä. Käytännössä kokeilu kannattaa tehdä hostatun API:n (`kimi-k3.1-pro`) tai Ollaman pilvitarjonnan kautta, ei omalla raudalla.

## Repot ja yhteisön tekniikat

**max-sixty/worktrunk GitHub trendingissä** (trending 4.11.) `[Kokeile]` - Rust-CLI, joka paketoi git worktreet rinnakkaisten AI-agenttien käyttöön. Esimerkiksi `wt switch -c -x claude feat` luo haaran ja worktreen ja käynnistää niihin Claude Coden. Työkalu tarjoaa pluginin Claude Codelle, Codexille ja Geminille. Claude Coden omat eristetyt worktreet voi ohjata sen kautta, jolloin niihin pätevät samat nimeämiskäytännöt ja hookit. `wt list --full` näyttää haarakohtaisen CI-tilan ja AI-yhteenvedot. MIT-lisenssi, uusin versio 0.61.0. [GitHub](https://github.com/max-sixty/worktrunk) · [Claude Code -ohje (docs.rs)](https://docs.rs/crate/worktrunk/latest/source/docs/static/claude-code.md)
*Miksi tärkeä / mitä kokeilla:* Jos ajatte useita Claude Code -sessioita rinnakkain samassa repossa, kokeilkaa `cargo install worktrunk` ja `wt switch -c -x claude <haara>` käsin hallittujen worktreeiden sijaan.

**vercel-labs/agent-desktop** (v1.0.0 julkaistu 28.10., trending 4.11.) `[Kokeile]` - Apache-2.0-lisensoitu Rust-CLI ja C-kirjasto, jolla agentit lukevat ja ohjaavat työpöytäsovelluksia käyttöjärjestelmän accessibility-puun kautta kuvakaappausten sijaan. Tuettuja ovat macOS, Windows ja Linux. Työkalussa ei ole omaa mallia, vaan agentti kutsuu sitä työkaluna. Se oli 4.11. trendingin nopeimmin noussut repo (noin 3 800 tähteä päivässä). Vercelin oman ilmoituksen mukaan token-säästö tiheissä Electron-sovelluksissa on 78–96 %, mutta riippumatonta mittausta ei ole. [MarkTechPost](https://www.marktechpost.com/2026/10/31/vercel-labs-agent-desktop-computer-use/) · [Asennus ja tietoturva (aicybr)](https://aicybr.com/blog/vercel-agent-desktop-accessibility-tree-ai-agent-cli-setup-security)
*Miksi tärkeä / mitä kokeilla:* Työkalu sopii WPF- tai WinForms-sovellusten UI-savutestaukseen agentilla. Ajakaa se kuitenkin vain eristetyssä VM:ssä, koska työkalulla on täysi pääsy työpöytään.
