# AI-aamuraportti - 2026-11-26

## Päivän tärkeimmät

- GitHub Copilot CLI 1.0.116 (25.11.) toi `env`-asetuksen, jolla ympäristömuuttujat menevät kaikille Copilotin käynnistämille prosesseille (shell, LSP, MCP-palvelimet, hookit). Lisäksi CLI varoittaa nyt, jos plugin ja erillinen MCP-palvelin osoittavat samaan endpointiin.
- Chrome DevTools MCP 1.14.0 tuo `inspect-in-devtools`-skillin ja Claude Code -plugin-komennon. Lisäksi se näyttää service workerien verkkopyynnöt ja laskennalliset CSS-tyylit, mistä on suoraa hyötyä Angular-frontendien debuggauksessa agentin kanssa.
- Claude Codesta ei tullut uutta versiota (uusin on yhä 2.1.332). Uusia malleja tai agentteihin kohdistuvia CVE:itä ei löytynyt ikkunassa.
- Anthropicin insinööriblogin mukaan Messages API:n taustajärjestelmä on siirretty Pythonista Rustiin. Siirto tehtiin pitkälti Clauden kirjoittamalla koodilla, ja se validoitiin varjoliikenteellä.
- Neljän päivän päästä on muutoksia: 30.11. poistuvat Sonnet 4.5 ja Opus 4.8:n fast mode, ja 1.12. Gemini 4 -hinnat nousevat ja Foundryn Copilot harnessin laskutus alkaa.

## Kehitystyökalut ja agentit

**GitHub Copilot CLI 1.0.116** (julkaistu 25.11.) `[Kokeile]` - Tämän version olennaiset muutokset agenttityönkulkujen kannalta:
- Uusi `env`-asetus asettaa ympäristömuuttujat kaikille Copilotin käynnistämille prosesseille (shell-komennot, paikalliset LSP- ja MCP-palvelimet, hookit ja laajennukset), sandboxin kanssa tai ilman.
- Jos plugin ja erillinen MCP-palvelin yhdistävät samaan endpointiin, CLI varoittaa ja näyttää `/mcp`-näkymässä, miten toisen saa pois päältä.
- `-i`-kehote, repositorion aloituskehote ja palautettu ajastus odottavat nyt enintään 30 sekuntia kansioluottamuksen käynnistämiä MCP-palvelimia, jotta ensimmäisessä pyynnössä on mukana niiden työkalut.
- Assisted Permissions huomioi myöhemmin chatissa annetut hyväksynnät ja niiden perumiset, myös sessiotason hyväksynnät.
- PowerShell-komennot, joiden parametrinimessä on numeroita (esim. `-ExpectedSha256`), noudattavat taas allow-sääntöjä eivätkä vaadi koko skriptin hyväksyntää.
- Pitkien sessioiden muistivuoto korjattiin.

Esiversio 1.0.117-2 ilmestyi tänä aamuna. [changelog.md](https://github.com/github/copilot-cli/blob/main/changelog.md)
*Miksi tärkeä / mitä kokeilla:* Jos MCP-palvelimet tarvitsevat esim. `AZURE_DEVOPS_ORG`- tai proxy-muuttujia, siirtäkää ne Copilot CLI:n `env`-asetukseen wrapper-skriptien sijaan. Tarkistakaa sitten `/mcp`-näkymästä, onko jokin palvelin käytössä kahteen kertaan sekä pluginin että erillisen konfiguraation kautta.

Muuta: Claude Code (2.1.332), Claude Agent SDK (0.3.332), Codex CLI (vakaa 0.172.0, alpha 0.174.0-alpha.6 25.11.) ja Gemini CLI (0.71.1) eivät saaneet uusia vakaita versioita ikkunassa. Cursorista, JetBrains AI:sta ja Devin Desktopista (ent. Windsurf) ei löytynyt uutta.

## Pluginit, skillit ja MCP

**Chrome DevTools MCP 1.14.0** (julkaistu 24.11., uutisoitu 25.11.) `[Kokeile]` - Googlen Chrome DevTools -tiimin MCP-palvelimen uusi versio. Muutokset:
- Uusi `inspect-in-devtools`-skill ja Claude Code -plugin-komento.
- Service workerien verkkopyynnöt ja konsoliviestit näkyvät nyt.
- `get_css_styles` palauttaa laskennalliset tyylit ja ratkaisee CSS-muuttujien arvot.
- Palvelin listaa virheet, joita sivu nostaa työkalun ajon aikana.
- Verkkoon voi mockata abort- ja allow-origin-vastauksia.
- Uusi `--backgroundNewPages`-lippu pitää uudet välilehdet taustalla.
- WSL2-asiakkaiden POSIX-polut toimivat Windows-palvelimen kanssa.

[CHANGELOG](https://github.com/ChromeDevTools/chrome-devtools-mcp/blob/main/CHANGELOG.md) · [npm](https://www.npmjs.com/package/chrome-devtools-mcp)
*Miksi tärkeä / mitä kokeilla:* Asentakaa Claude Codeen plugin (`/plugin marketplace add ChromeDevTools/chrome-devtools-mcp`, sitten `/plugin install chrome-devtools-mcp@chrome-devtools-plugins`). Antakaa agentin sitten debugata Angular-sovelluksen tyyli- tai service worker -ongelma laskennallisten tyylien ja SW-verkkopyyntöjen avulla. WSL2-korjaus auttaa, jos ajatte Claude Codea WSL:ssä ja Chromea Windowsissa.

Muuta: `@anthropic-ai/sdk` 1.14.0 (24.11.) toi lähinnä admin- ja compliance-rajapintoja (Google-hallitut datakontrollit, compliance review -tapaukset). `@modelcontextprotocol/sdk` on yhä 1.32.2, `@openai/agents` 0.22.0 ja `@langchain/langgraph` 1.7.5. Vercel AI SDK nousi versioon 7.0.182 (patch).

## Toimintatavat ja arkkitehtuuripatternit

**Messages API:n uudelleenkirjoitus Rustiksi Clauden avulla, validointi varjoliikenteellä** (Anthropicin insinööriblogi, 25.11.) `[Tiedoksi]` - Anthropic kertoo siirtäneensä Messages API:n taustajärjestelmän Python-monoliitista Rustiin. Toissijaisten lähteiden mukaan Claude kirjoitti suurimman osan koodista. Uusi toteutus rakennettiin kokonaan rinnalle eikä endpoint kerrallaan, ja sitä ajettiin varjoliikenteellä vanhaa vastaan ennen käyttöönottoa. Raportoitu 40–50 %:n CPU-säästö on podcastissa esitetty arvio, jota ei ole varmennettu. Itse blogipostausta ei saatu luettua, joten yksityiskohdat ovat hakutulosten ja toissijaisten lähteiden varassa. [Anthropic Engineering](https://www.anthropic.com/engineering) · [explainx.ai-analyysi](https://explainx.ai/blog/anthropic-messages-api-rust-rewrite-claude-wrote-code-cpu-40-50-percent-claimed-vs-verified-2026)
*Miksi tärkeä / mitä kokeilla:* Jos teillä on agentilla tehtävä iso migraatio (esim. vanha .NET Framework -palvelu .NET 9:ään), käyttäkää samaa mallia. Agentti kirjoittaa rinnakkaisen toteutuksen, tuotantoliikenne peilataan molempiin (esim. Azure API Managementin tai YARP:n kautta), ja vastauksien eroja verrataan ennen kuin liikenne käännetään uudelle toteutukselle.

## Syväluentaehdokkaat

- **Chrome DevTools MCP frontend-agenttityöhön:** Laskennalliset tyylit, service workerit ja ajonaikaiset sivuvirheet tekevät siitä nyt käyttökelpoisen Angular-bugien juurisyyanalyysiin. Kokeilkaa pluginia yhteen oikeaan UI-bugiin ja kirjatkaa, säästyikö manuaalista DevToolsin käyttöä.
- **Varjoliikenne agentin tekemän migraation validointiin:** Anthropicin Rust-siirto on tähän asti suurin julkinen esimerkki tavasta, jolla agentin kirjoittama korvaava toteutus todennetaan tuotantoliikenteellä. Miettikää, mihin tulevaan .NET-modernisointiin pattern sopisi ja millä työkalulla liikenteen peilaus Azuressa onnistuu.
