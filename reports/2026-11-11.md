# AI-aamuraportti - 2026-11-11

## Päivän tärkeimmät

- Microsoft korjasi 10.11. VS Codesta kriittisen MCP-haavoittuvuuden (CVE-2026-120779, CVSS 9.6), jossa haitallinen MCP-palvelin saattoi ajaa komentoja muotoillun ilmoituslinkin kautta. Päivittäkää VS Code vähintään versioon 1.145.3.
- Visual Studio 2026 18.12:ssa Copilot Chat käyttää nyt oletuksena samaa Copilot SDK -valjasta kuin Copilot CLI ja VS Code. Microsoftin testissä samalla mallilla ratkesi 124/157 C#-tehtävää, kun vanha toteutus ratkaisi 103.
- .NET 11 julkaistiin 10.11. (STS, C# 15). `dotnet new mcpserver` tulee nyt SDK:n mukana, ja Microsoft.Extensions.AI ja Agent Framework ovat julkaisun virallinen AI-pino.
- Gemini 4 Carbon on yleisesti saatavilla GitHub Copilotissa (Pro+, Max, Business, Enterprise). Se on oletuksena päällä organisaatioissa, joissa admin ei ole kytkenyt uusien mallien oletussallintaa pois.
- Claude Codeen ei tullut uutta versiota 2.1.322:n (10.11.) jälkeen.

## Pluginit, skillit ja MCP

**`dotnet new mcpserver` nyt vakaassa .NET 11 SDK:ssa** (julkaistu 10.11.) `[Kokeile]` - MCP-palvelimen projektipohja tulee nyt .NET 11 SDK:n mukana, joten erillistä `Microsoft.McpServer.ProjectTemplates`-asennusta ei tarvita. Pohja toimi jo Preview 4:stä alkaen, mutta nyt se on GA-SDK:ssa. Julkaisu nimeää .NETin AI-pinoksi Microsoft.Extensions.AI:n (`IChatClient`, `IEmbeddingGenerator`) mallikutsuihin, MCP:n työkaluintegraatioon ja Microsoft Agent Frameworkin agentteihin ja työnkulkuihin. [.NET Blog](https://devblogs.microsoft.com/dotnet/announcing-dotnet-11/) · [Microsoft Learn: build MCP server](https://learn.microsoft.com/dotnet/ai/quickstarts/build-mcp-server)
*Miksi tärkeä / mitä kokeilla:* Tehkää sisäisestä API:sta tai Azure DevOps -kyselyistä MCP-palvelin komennolla `dotnet new mcpserver -n Team.Mcp`, tarkistakaa vaihtoehdot komennolla `dotnet new mcpserver --help` (stdio/HTTP, Native AOT) ja kytkekää palvelin Claude Codeen komennolla `claude mcp add`.

Muuta: MCP-spesifikaatioon tai `@modelcontextprotocol/sdk`-pakettiin ei tullut ikkunassa uusia versioita (SDK yhä 1.32.2 / 23.10.). Claude Agent SDK (TS) 0.3.322 julkaistiin 10.11. samassa tahdissa kuin Claude Code 2.1.322.

## Toimintatavat ja arkkitehtuuripatternit

**Valjas on mitattava muuttuja, ei pelkkä malli** (dokumentoitu 10.11.) `[Kokeile]` - Visual Studion siirtymä Copilot SDK:hon nosti ratkaistujen C#-tehtävien määrän 103:sta 124:ään (157:stä) mallia vaihtamatta. Tulos muistuttaa, että työkalut, kontekstin kokoaminen ja agenttiluuppi vaikuttavat tulokseen yhtä paljon kuin mallivalinta. Käytännössä Claude Coden päivitykset, CLAUDE.md:n muutokset, skillit ja hookit kannattaa evaluoida samalla tavalla kuin mallivaihdokset. [Visual Studio Blog](https://devblogs.microsoft.com/visualstudio/copilot-in-visual-studio-just-got-a-major-upgrade/)
*Miksi tärkeä / mitä kokeilla:* Kootkaa 10–20 tiimin oikeaa, jo mergettyä PR:ää toistettavaksi evaliksi ja ajakaa se aina, kun vaihdatte työkaluversiota, ohjetiedostoa tai effort-tasoa, ei vain mallia vaihtaessanne.

**MEAI + MCP + Agent Framework .NET-agenttien referenssiarkkitehtuurina** (dokumentoitu 10.11.) `[Kokeile]` - .NET 11 -julkaisu jakaa agenttisovelluksen kolmeen kerrokseen. Microsoft.Extensions.AI on mallikerros, jonka takana mallintarjoajan voi vaihtaa (Azure OpenAI, Anthropic, paikallinen). MCP on työkalukerros, joka on jaettavissa myös Claude Codelle ja Copilotille. Agent Framework hoitaa orkestroinnin ja työnkulut. Kun työkalut ovat MCP-palvelimina eivätkä sovelluksen sisäisinä funktioina, samat työkalut palvelevat sekä tuotantoagenttia että kehittäjien koodausagentteja. [.NET Blog](https://devblogs.microsoft.com/dotnet/announcing-dotnet-11/)
*Miksi tärkeä / mitä kokeilla:* Jos rakennatte Azureen .NET-agenttia, kirjoittakaa sen työkalut ensin erilliseksi MCP-palvelimeksi ja kutsukaa mallia `IChatClient`-rajapinnan kautta, jolloin mallin vaihto on konfiguraatiomuutos.

## Tietoturvavahti

**CVE-2026-120779: VS Coden MCP-elicitation-ilmoitukset, RCE (CVSS 9.6)** (julkaistu 10.11.) `[Kokeile]` - Kun MCP-palvelin lähetti elicitation-pyynnön, VS Code näytti sen varapolulla ilmoituksena, ja palvelimen määräämä viestisisältö saattoi muuttua interaktiiviseksi VS Code -komentolinkiksi. Haitallinen MCP-palvelin pystyi näin ajamaan komentoja käyttäjän oikeuksilla, jos käyttäjä klikkasi ilmoitusta. Samassa erässä korjattiin myös CVE-2026-120782 (CVSS 7.8, koodi-injektio) ja CVE-2026-120780 (pääsynhallinta). Liittyvissä GitHub-issueissa kuvataan RCE validoimattomien MCP SSE -endpointtien ja haitallisten MCP-asennuslinkkien kautta. Haittakäyttöä ei ole havaittu. Haavoittuvia ovat versiot ennen 1.145.3:a. [CVE.org](https://www.cve.org/CVERecord?id=CVE-2026-120779) · [microsoft/vscode #347426](https://github.com/microsoft/vscode/issues/347426) · [#347428](https://github.com/microsoft/vscode/issues/347428) · [#347430](https://github.com/microsoft/vscode/issues/347430) · [Rapid7](https://www.rapid7.com/blog/post/em-patch-tuesday-november-2026/)
*Miksi tärkeä / mitä kokeilla:* Tarkistakaa versio komennolla `code --version` ja päivittäkää vähintään versioon 1.145.3 kaikilla koneilla ja dev containereissa. Siihen asti yhdistäkää vain tunnettuihin MCP-palvelimiin, älkääkä avatko `vscode:`-MCP-asennuslinkkejä chatista tai sähköpostista.

**Marraskuun Patch Tuesday: lisää VS Code -korjauksia** (julkaistu 10.11.) `[Kokeile]` - Microsoftin marraskuun päivityserässä on yli tuhat CVE:tä, joista yhtä on käytetty hyökkäyksissä (CVE-2026-124194, ei kehitystyökaluissa). VS Codelle tuli MCP-korjausten lisäksi CVE-2026-121662 (RCE, komentoinjektio) ja CVE-2026-121663 (tietoturvaominaisuuden ohitus), molemmat luokitukseltaan Important. [Qualys](https://blog.qualys.com/vulnerabilities-threat-research/2026/11/10/microsoft-patch-tuesday-november-2026-security-update-review) · [Tenable](https://www.tenable.com/blog/microsoft-november-2026-patch-tuesday-addresses-1093-cves-cve-2026-124194) · [Talos](https://blog.talosintelligence.com/microsoft-patch-tuesday-for-november-2026/)
*Miksi tärkeä / mitä kokeilla:* Varmistakaa, että Visual Studio (18.12) ja VS Code päivittyvät samalla kierroksella kuin Windows-päivitykset, ja lisätkää kehitystyökalut patch-hallinnan raportointiin, jos niitä ei siellä vielä ole.
