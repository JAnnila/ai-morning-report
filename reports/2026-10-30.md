## Kehitystyökalut ja agentit

**Claude Code 2.1.314** (julkaistu 30.10.) `[Kokeile]` - Uusi `permissions.blockWritesOutsideWorkingDirectories` saa Write-, Edit- ja NotebookEdit-työkalut kieltäytymään kaikista työhakemistojen ulkopuolisista poluista lupatilasta riippumatta. Se on kirjoituspuolen pari syyskuussa tulleelle `blockReadsOutsideWorkingDirectories`-asetukselle. Lisäksi VS Code ja Claude Desktopin Code-välilehti tiivistävät joutilaaksi jääneen yli 200K tokenin keskustelun automaattisesti. `claude -p` palauttaa käynnistysvirheessä nyt koodin 1 ja virheilmoituksen, kun se aiemmin palautti 0 ilman tulostetta. Admin-rajattu effort-taso ei myöskään enää kaada sessiota, vaan Claude Code laskee tasoa ja yrittää uudelleen. Claude Agent SDK 0.3.314 julkaistiin samaan aikaan. [CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)
*Miksi tärkeä / mitä kokeilla:* Lisää tiimin jaettuun `.claude/settings.json`:iin `"permissions": {"blockWritesOutsideWorkingDirectories": true}` ja varmista Azure Pipelines -ajoissa, että `claude -p` -askel nyt oikeasti epäonnistuu startup-virheessä eikä mene läpi tyhjänä.

**GitHub Copilot in JetBrains: next edit suggestions GA** (julkaistu 28.10.) `[Kokeile]` - Copilotin NES on nyt yleisesti saatavilla JetBrains-IDE:issä. GitHubin mukaan ehdotukset ovat laadukkaampia ja paremmin kontekstitietoisia, ja inline-katselmointi ja hyväksyminen toimivat sujuvammin. Inline-completionit ja NES on myös sovitettu yhteen niin, että hyväksytyn completionin jälkeen tulee jatkoehdotus. VS Coden Universe-julkaisut käsiteltiin eilen; tämä on JetBrains-puolen vastine. [GitHub Changelog](https://github.blog/changelog/2026-10-28-github-copilot-in-jetbrains-universe-releases/)
*Miksi tärkeä / mitä kokeilla:* Rider-käyttäjät (.NET) voivat ottaa ominaisuuden käyttöön kohdasta Settings > GitHub Copilot > Completions > Enable Next Edit Suggestions ja kokeilla sitä monitiedostoisissa uudelleennimeämisissä.

## Toimintatavat ja arkkitehtuuripatternit

**Drew Breunig: "The State of Context Engineering"** (julkaistu 24.10.) `[Tiedoksi]` - Kirjoitus perustuu AGNTCon-puheeseen "Context Fails & Fixes". Sen ydinväite on, että insinöörin tärkein päätös on rajata, mikä hoidetaan deterministisellä koodilla ja mikä jätetään mallin harkintaan. Breunig nimeää korjauskeinoksi muun muassa "context quarantinen": subagentti aloittaa tyhjällä historialla mutta toimii samassa ympäristössä, ja pääagentille palaa vain tulos. [dbreunig.com](https://www.dbreunig.com/2026/10/24/the-state-of-context-engineering.html)
*Miksi tärkeä / mitä kokeilla:* Käy läpi yksi oma agenttityönkulku ja siirrä deterministiset vaiheet, kuten tiedostojen haun, formatoinnin ja ADO-kenttien täytön, skripteiksi tai hookeiksi; ohjaa sen jälkeen kohinaiset hakutehtävät subagentille.

**Ohjetiedostot hyökkäyspintana: MALFEX ja haitallinen AGENTS.md** (julkaistu 26.10.) `[Kokeile]` - Aviatrixin tapauskuvauksessa kehittäjän Downloads-kansiosta löytyi AGENTS.md, joka ohjeisti koodausagenttia asentamaan tunnetusti haitallisen npm-paketin `function-color`. Yritys havaittiin ja pysäytettiin ennen koodin suoritusta. Patterni on yleinen: kaikki agentin automaattisesti lukemat ohjetiedostot (AGENTS.md, CLAUDE.md, `.mcp.json`) ovat käytännössä suoritettavaa syötettä. [Aviatrix Threat Research](https://aviatrix.ai/threat-research-center/malicious-agentsmd-downloads-folder-ai-coding-agent-malfex-npm-2026/)
*Miksi tärkeä / mitä kokeilla:* Älä käynnistä agenttia luottamattomissa kansioissa (Downloads, kloonatut vieraat repot) ilman sandboxia, ja lisää PreToolUse-hook, joka vaatii vahvistuksen jokaiselle `npm install`- ja `pip install` -komennolle, jonka paketti ei ole lukitustiedostossa.

## Uudet mallit

**Gemini 4 Carbon** (julkaistu 28.10., uutisoitu 28.–29.10.) `[Seuraa]` - Google DeepMindin uusi frontier-malli on suunnattu monipäiväisiin autonomisiin kehitystyönkulkuihin ja kyberpuolustukseen. Googlen omissa, ilman guardraileja ajetuissa testeissä tulokset ovat SEC-bench Pro 88,2 %, ExploitGym 54,8 % ja CWE-bench 71,0 %, ja turvallisen koodin onnistumisprosentti on yli kaksinkertainen Argoniin verrattuna. Artificial Analysis Intelligence Index v5:n kärjessä malli on 59 pisteellä, mutta agenttikoodauksessa se jää raporttien mukaan hieman Opus 5.5:n taakse. Pääsy on toistaiseksi vain Fairwind-ohjelman tietoturvapuolustajilla; laajempi saatavuus kehittäjille on "tulossa pian". [Google Blog](https://blog.google/innovation-and-ai/models-and-research/gemini-models/introducing-gemini-4-carbon/) · [Help Net Security](https://www.helpnetsecurity.com/2026/10/29/google-gemini-4-carbon-model/)
*Miksi tärkeä / mitä kokeilla:* Ei vielä kokeiltavissa; kun API aukeaa, vertaa sitä Opus 5.5:een omassa tietoturvakatselmointi- tai haavoittuvuuskorjaustehtävässä ennen kuin vaihdat mallia.

## Tietoturvavahti

**Claude Code 2.1.314: sandbox- ja politiikkakorjaukset** (julkaistu 30.10.) `[Kokeile]` - Versio korjaa useita tietoturvan kannalta olennaisia vikoja. Sandbox-suojaukset eivät koskeneet worktreetä, johon siirryttiin `claude -p --resume`- tai `--continue`-ajossa. Pelkästään etähallinnoiduissa asetuksissa määritelty `forceRemoteSettingsRefresh` lakkasi toimimasta, kun tallennettu kopio vanheni, jolloin sessio saattoi käynnistyä ilman politiikkaa, jos palvelimeen ei saatu yhteyttä. `--setting-sources`-valitsimella poissuljettu asetustiedosto toimitti silti joitakin asetuksia, kuten auto mode -sääntöjä ja tallennettuja lupahyväksyntöjä. Lisäksi Monitor-työkalun käynnistämät shell-komennot ohittivat Bash-hookit. [CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)
*Miksi tärkeä / mitä kokeilla:* Jos ajat headless-agentteja `--resume`-valitsimella tai luotat managed settings -politiikkaan, päivitä kaikki koneet ja CI-imaget versioon ≥ 2.1.314 (`npm i -g @anthropic-ai/claude-code@2.1.314`).

## Syväluentaehdokkaat

- **Claude Coden kirjoitus- ja lukurajaukset yhdessä:** `blockReadsOutsideWorkingDirectories`, `blockWritesOutsideWorkingDirectories` ja sandbox muodostavat nyt kokonaisuuden, jolla agentin voi rajata repoonsa ilman omia PreToolUse-hookeja. Kannattaa rakentaa tiimille yksi managed settings -pohja ja testata se headless-ajoissa (`-p --resume`), joissa tämän päivän korjaukset osuivat.
- **Breunigin "deterministinen koodi vs. malli" -jako:** se on konkreettinen kehys, jolla voi pienentää agenttiajojen tokenikulutusta ja epädeterministisyyttä. Sopii hyvin ADO-integraatioihin, joissa suuri osa vaiheista on kuitenkin sääntöpohjaisia.
