# AI-aamuraportti - 2026-11-03

## Päivän tärkeimmät

- Anthropic julkaisi 2.11. Messages API:in message threads -betan. Pitkissä agenttisessioissa lähetetään jatkossa vain uudet viestit, ja 500K–1M tokenin pyynnöissä mediaani time-to-first-token laskee noin 35 %. Ominaisuus on käytössä oletuksena useimmilla Claude Code -käyttäjillä.
- Claude Code 2.1.317 (2.11.) kysyy luvan ennen kuin web- tai shell-työkalu lähettää käyttäjän tilin sähköpostiosoitteen verkkoon. Lisäksi se varoittaa `/schedule`-tehtävistä, joille on tullut pyytämättömiä connectoreita, ja korjaa projektin MCP-palvelimien katkeamisen desktop-sessioissa.
- Agent SDK:n hook-callbackeille tuli `onFailure: "block"`: jos vartijana toimiva callback kaatuu, toiminto estetään eikä sitä päästetä läpi.
- LangChainin "New context engineering challenges in late 2026" (2.11.) nimeää uudeksi pullonkaulaksi asynkroniset subagentit, joiden aikana pääagentin pitää pysyä responsiivisena.
- Qwen4:ää ei julkaistu viikon alussa, vaikka Alibaban CTO:n kerrottiin luvanneen sen "ensi viikolla". Mallivalintoja ei kannata vielä lukita.

## Kehitystyökalut ja agentit

**Claude Messages API: message threads (public beta)** (julkaistu 2.11.) `[Kokeile]` - Ensimmäisen täyden pyynnön jälkeen asiakas lähettää vain uudet viestit, ja API pitää keskustelun tallessa. Beta-header on `message-threads-2026-08-12`. Thread vanhenee 5 minuuttia viimeisen pyynnön jälkeen ja poistetaan viimeistään tunnin kuluttua. Threadeja ei voi listata, lukea eikä poistaa API:n kautta, joten oma historia ja täysi uudelleenlähetys on pidettävä varalla. Ominaisuus toimii Claude API:ssa, Claude Platform on AWS:ssä, Anthropicin hallinnoimilla Claude-malleilla Google Cloudissa ja Claude in Microsoft Foundryssa. [Claude: Make long-running agents faster with message threads](https://claude.com/resources/articles/message-threads) · [Messages API docs](https://platform.claude.com/docs/en/build-with-claude/working-with-messages)
*Miksi tärkeä / mitä kokeilla:* Jos teillä on oma agenttiluuppi, esimerkiksi .NET-palvelu Foundryn Clauden päällä, lisää `anthropic-beta: message-threads-2026-08-12` ja mittaa TTFT pitkissä sessioissa. Toteuta samalla fallback, joka lähettää koko historian uudelleen, kun thread on vanhentunut.

**Claude Code 2.1.317** (julkaistu 2.11.) `[Kokeile]` - Iso korjausjulkaisu. Projektin ja paikalliset MCP-palvelimet eivät enää katkea ensimmäisen vuoron jälkeen desktop-sessioissa. Lisäksi `claude -p` palauttaa exit-koodin 1, jos transkriptin kirjoitus epäonnistuu täyden levyn tai kiintiön takia, ja TLS-tarkastavien proxyjen "unable to get local issuer certificate" -virhe on korjattu. OTel-dataan lisättiin attribuutit `anthropic.plan`, `anthropic.seat_type`, `anthropic.provider` ja `anthropic.custom_base_url`, ja Claude apps gateway sai kustannusraportin `GET /v1/organizations/analytics/cost`. [CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)
*Miksi tärkeä / mitä kokeilla:* Päivitä (`npm i -g @anthropic-ai/claude-code@2.1.317`), jos CI-ajot käyttävät `claude -p`:tä. Hiljaa epäonnistuneet ajot näkyvät nyt putkessa virheinä. Jos käytätte gatewayta, hae kustannusraportista kulut per kehittäjä ja IdP-ryhmä.

## Pluginit, skillit ja MCP

**Agent SDK -hookit: `onFailure: "block"`** (julkaistu 2.11., Claude Code 2.1.317) `[Kokeile]` - Agent SDK:n hook-callbackille voi nyt asettaa `onFailure: "block"`, jolloin poikkeuksen heittävä tai muuten epäonnistuva callback estää toiminnon. Aiemmin toiminto pääsi läpi. Samassa julkaisussa korjattiin myös kaksi muuta asiaa. Stdio-MCP-palvelimet saivat tyhjän `AWS_BEARER_TOKEN_BEDROCK`-arvon, kun env-konfiguraatio asetti sen tyhjäksi; nyt muuttuja jätetään asettamatta. Toiseksi claude.ai-connector raportoitiin virheellisesti rikkinäiseksi cloud-sessioissa, kun synkattu plugin sisälsi saman palvelimen. [CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)
*Miksi tärkeä / mitä kokeilla:* Lisää `onFailure: "block"` kaikkiin SDK-hookeihin, jotka toimivat turvarajana, kuten salaisuuksien tai tuotantokomentojen estoissa. Muuten kaatunut tarkistus on käytännössä sama kuin hyväksytty toiminto.

## Toimintatavat ja arkkitehtuuripatternit

**LangChain: "New context engineering challenges in late 2026"** (julkaistu 2.11.) `[Seuraa]` - Harrison Chase kuvaa uutta ongelmakenttää: agentit ajavat yhä pidempään ja kutsuvat työkaluja ja toisia agentteja, jotka nekin ajavat pitkään. Silti käyttäjälle vastaavan pääagentin on pysyttävä responsiivisena. Avoimia kysymyksiä ovat, miten pääagentille ilmoitetaan taustatyön valmistumisesta ja miten tilanne käsitellään, kun pääagentti on vielä kesken tai jo valmis. LangChainin aiempi ratkaisu Deep Agentsissa on async-subagentti, joka palauttaa heti task-ID:n. Kun subagentti valmistuu, se käynnistää uuden pääagentin ajon tuloksen kanssa, joten pollausluuppia ei tarvita. [LangChain Blog](https://www.langchain.com/blog/context-engineering-challenges-late-2026) · [Running Subagents in the Background](https://www.langchain.com/blog/running-subagents-in-the-background)
*Miksi tärkeä / mitä kokeilla:* Jos rakennatte ADO-integraatioon orkestroijaa, älä odota synkronisesti pitkiä subagentteja. Käynnistä ne taustalle, tallenna task-ID ja jonota pääagentille uusi vuoro valmistumistapahtumasta, esimerkiksi Azure Service Bus -viestillä.

## Tietoturvavahti

**Claude Code 2.1.317: sähköpostin vuotoesto ja `/schedule`-connector-varoitus** (julkaistu 2.11.) `[Kokeile]` - Claude Code kysyy nyt ennen kuin web- tai shell-työkalun kutsu lähettää käyttäjän tilin sähköpostiosoitteen verkkoon. `/schedule` varoittaa, jos uusi cloud-ajastettu tehtävä saa connectoreita, joita käyttäjä ei pyytänyt, ja kertoo miten ne poistetaan. Lisäksi Remote Control- ja SDK-isännät eivät enää tarjoa "don't ask again" -valintaa modien työkalukutsuille, ja tmux- tai iTerm2-paneeleissa ajetut agent team -jäsenet eivät enää käynnisty auto modessa, kun lead-sessio on manual-tilassa. [CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)
*Miksi tärkeä / mitä kokeilla:* Käy läpi tiimin ajastetut cloud-tehtävät (`/schedule` → list) ja poista connectorit, joita tehtävä ei tarvitse. Pienempi oikeuspinta tarkoittaa pienempää prompt injection -riskiä.

**Adversa: marraskuun AI-koodausagenttien haavoittuvuuskooste** (uutisoitu marraskuun 2026 alussa; tarkkaa päivää ei löytynyt) `[Tiedoksi]` - Koosteessa on kaksi kehitystyökaluihin liittyvää tapausta. Straiker STAR Labsin "Session Inception" -tutkimuksessa Claude Code -sessio käynnisti haitallisessa repossa lapsisession, joka ei perinyt vanhemman suojauksia, ja repon SessionStart-hook pystyi vuotamaan kehittäjän dataa. Anthropic sulki raportin luokituksella Informative. Toinen tapaus on CVE-2026-103572 (CVSS 8.8): Visual Studion Copilotissa ja SSMS:ssä tiedostonimen loppupiste ohitti konfiguraatiotiedostojen, kuten `.mcp.json`:n, suojauksen ja mahdollisti komentojen suorittamisen epäsuoralla prompt injectionilla. Microsoft korjasi haavoittuvuuden 13.10. [Adversa AI](https://adversa.ai/blog/top-ai-coding-agent-security-resources-november-2026/) · [Straiker](https://www.straiker.ai/blog/session-inception-spawning-a-child-claude-session-to-bypass-parent-guardrails) · [Embrace The Red](https://embracethered.com/blog/posts/2026/visual-studio-copilot-remote-code-execution/)
*Miksi tärkeä / mitä kokeilla:* Varmista, että Visual Studio ja SSMS ovat lokakuun päivitystasolla. Älä aja Claude Codea vieraissa repoissa ennen kuin olet tarkistanut niiden `.claude/settings.json`-hookit (`cat .claude/settings.json | jq .hooks`).
