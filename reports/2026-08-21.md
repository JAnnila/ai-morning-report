**Claude Code v2.1.237 – "Concise"-tyyliasetus ja prompt-caching-korjaus (Anthropic, 20.8.2026)**

Anthropic julkaisi 20.8. Claude Code -version 2.1.237. Kaksi merkittävää muutosta:

- **Sisäänrakennettu "Concise"-tyyliasetus**: Claude Code saa nyt neljännen output-tyyliasetuksen (Default, Proactive, Explanatory, Learning). Concise-tilassa Claude johdattaa suoraan tulokseen, jättää johdannon ja narratiivisen kerronnan pois, mutta tekee työn yhtä perusteellisesti. Asetus: `/config` → Output style → Concise, tai `settings.json`:ssa `"outputStyle": "Concise"`. Vertailu: v2.1.236:n `ANTHROPIC_DEFAULT_MODEL` asetti oletusmallin; tämä uusi asetus konfiguroi vastaustyylin.
- **Prompt-caching-bugikorjaus LLM-gatewayn kautta**: Sessiot jotka käyttivät omaa base URL:ia tai LLM-gatewayta (esim. LiteLLM, LLM Gateway) saattoivat aiemmin saada vanhentuneita cachetuloksia. Tämä on korjattu.

*Miksi tärkeä / mitä kokeilla:* Testaa Concise-tyyliä koodaustyönkuluissa joissa haluat lyhyen, suoran vastauksen ilman selittelyä – erityisesti hyödyllinen agenttisessioissa joissa vastaukseen käytettyä tokenimäärää halutaan minimoida. Jos käytät LLM-gatewayta Claude Coden alla, päivitä 2.1.237:ään korjataksesi mahdolliset prompt-caching-epäjohdonmukaisuudet.

**FreeToken: Frontier-luokan MoE-mallien ajaminen kannettavalla tietokoneella (FlashML, julk. arXiv 17.8.2026; HuggingFace trending 20.–21.8.)**

MIT/Berkeley/Stanford-tutkijoiden (Song Han, Matei Zaharia, Ion Stoica ym.) arXiv-paperi 2608.16157 nousi Hugging Facen trending-listalle noin 20.8. FreeToken on edge-natiivi Mixture-of-Experts -inferenssijärjestelmä joka kohdistaa MoE-mallien laskenta- ja muistitilan heterogeeniselle paikalliselle laitteistolle (GPU, CPU, isäntämuisti, yhteenliitännät) yhtenäisenä elastisena alustana. Tukee yli 20 MoE-mallia; toimii 8 GB:n kannettavan GPU:sta yhden workstation-GPU:n ympäristöön. Ominaisuudet: bandwidth-adaptiivinen CPU–GPU-yhteissuoritus, kaksoisvirtainen prefill-striimaus, globaali LRU-asiantuntijacache, graph-yhteensopiva suoritus ja FTW-pakattu mallimuoto. GitHub: [FlashML-org/FreeToken](https://github.com/FlashML-org/FreeToken); julkaisuportaali: flashml.ai.

*Miksi tärkeä / mitä kokeilla:* Jos agenttityönkulkuasi rajoittaa API-kustannus tai verkkoviive, FreeToken mahdollistaa DeepSeek- tai Qwen-pohjaisen MoE-mallin ajamisen paikallisesti henkilökohtaisella koneella. Lataa paperi ja asenna FreeToken – erityisesti kiinnostavaa verrata FTW-muodon latenssia GGUF-pohjaisiin llama.cpp-ajoihin.

## Tietoturvavahti

**isolated-vm: kriittinen sandbox escape (GHSA-864f-rcv7-6rh4) vaikuttaa suoraan AI-agenttikehyksiin – 1M+ latausta/vk (The Hacker News / Endor Labs, 20.8.2026)**

Endor Labs -tutkijat paljastivat 20.8. kriittisen tyyppisekaannushaavoittuvuuden `isolated-vm`-JavaScript-sandboxissa. Haavoittuvuus (GHSA-864f-rcv7-6rh4, CVE:tä ei vielä assigned) on isolated-vm:n C++-liimakerroksen ExternalCopy-mekanismissa: sandboxin sisällä ajettava koodi voi korruptoida isäntäprosessin muistia ja paeta sandboxin rajoista, mahdollistaen RCE:n isäntäkoneella.

**Kaikki versiot ≤ 7.0.0 haavoittuvia** – korjattu versioissa **6.2.0** ja **7.0.1**. npm-paketti saa yli miljoona latausta viikossa. Suoria käyttäjiä/osia ovat avoimen lähdekoodin AI-agenttikehykset: **n8n**, **Sim.ai**, **Mastra**, **Activepieces**. Jos käytät näitä suoraan tai epäsuorasti, sandboxisi on haavoittuvainen ennen päivitystä.

*Miksi tärkeä / mitä kokeilla:* Tarkista välittömästi `npm list isolated-vm` tai `pip show isolated-vm`-tyyppiset riippuvuudet kaikissa projekteissa – erityisesti jos ajat agentteja tai plugin-koodia epäluotetusta lähteestä sandboxetussa ympäristössä. Päivitä `isolated-vm` >= 7.0.1 tai 6.2.0. Koska CVE-numero puuttuu vielä, automatisoidut haavoittuvuusskannaukset eivät välttämättä löydä tätä GHSA-tunnisteen perusteella – käytä Bumblebee tai Endor Labsin pakettiversiotarkistusta.

**Claude Code -pohjainen automatisoidtu SAML-tutkimus löysi auth bypassen neljässä tuotteessa (Oblique Security, 20.8.2026)**

Eric Chiang (Oblique Security CTO) julkaisi 20.8. blogipostauksen "Hacking SAML with Claude Code" – automatisoidtu tutkimusputki Claude Opus -mallilla ja SAML-beachhead-mallilla löysi täydellisiä autentikaation ohitushaavoittuvuuksia neljässä SAML-toteutuksessa:

- **Authentik CVE-2026-57580**: XML-kommentti SAML NameID-arvossa; tietyssä account-matching-moodissa voidaan linkittää hyökkääjän ulkoinen identiteetti uhrin tilille. Korjattu versioissa 2026.2.6 ja 2026.5.5.
- **PHP litesaml/lightsaml**, **OneUptime** ja **Java saml-client**: signature wrapping -hyökkäyksiä, joissa XML-elementtejä siirretään niin että allekirjoitusvalidointi menee läpi väärän objektin yli.

Tutkimusmetodologia: Claude Opukselle annettiin uhkamalli ja sallittiin vapaasti tutkia SAML-kirjastojen signeeratun XML-datan käsittelyä. Malli löysi haavoittuvuuksia valmistajan kirjastoista joita niihin perehtynyt kehittäjä ei ollut huomannut.

*Miksi tärkeä / mitä kokeilla:* Jos organisaatiosi käyttää Authentikia SSO-ratkaisuna (suosittu open-source IdP), tarkista versio välittömästi ja päivitä ≥ 2026.2.6 tai 2026.5.5. Yleisemmin: Claude Code -pohjainen SAML-testaus on nyt dokumentoitu metodologia – harkitse käyttöä omille SAML-toteutuksillesi ennen seuraavaa security-auditointia.

## Hinnoittelu

**Azure OpenAI: cache write billing alkaa tänään 21.8.2026 (Microsoft, voimaan 21.8.2026)**

Azure OpenAI:n prompt-caching on tähän asti ollut write-vapaa: cacheen kirjoittaminen ei ole laskuttanut erikseen. Tämä subventio päättyy tänään. GPT-5.6-perheessä ja myöhemmissä malleissa cache-kirjoitukset alkavat laskuttaa **1,25× uncached input token -hinnalla** (`cache_write_tokens`-kentässä). Cache-lukeminen pysyy ennallaan: **0,10× uncached input -hinta** (90 % alennus). Vanhemmat mallit (ennen GPT-5.6:ta) eivät muutu.

Vaikutus: Korkean cache hit -raten arkkitehtuurit ovat edelleen kannattavia – kallis write amortisoidaan monilla halvoilla readeilla. Matalahittinen tai satunnainen cache-käyttö muuttuu nettona kalliimmaksi kuin ilman cachea.

*Miksi tärkeä / mitä kokeilla:* (1) Tarkista `cache_write_tokens` vs. `cached_input_tokens` API-vastauksissa – laske nykyinen hit-rate. Jos hit-rate < ~80 %, cache saattaa tuottaa nettokustannuksia. (2) Tarkista arkkitehtuuri: staattinen järjestelmäprompt isolla cacheyrityksellä kannattaa; lyhyet, usein vaihtuvat promptit ei. (3) Päivitä kustannusennusteet – aiemman käytön perusteella kirjoitukset olivat ilmaisia.
