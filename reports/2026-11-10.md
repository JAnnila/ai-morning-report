# AI-aamuraportti - 2026-11-10

## Päivän tärkeimmät

- Anthropic julkaisi 9.11. Claude Fable 5.2:n (`claude-fable-5-2`). Se on halvempi kuin 5.1 ($8/$40 per Mtok, aiemmin $10/$50), sillä on 1M kontekstin ja valinnainen fast mode, ja se on nyt Claude Coden oletusarvoinen Fable-malli versiosta 2.1.321 alkaen.
- Claude Code 2.1.321 korjaa useita tietoturvavikoja: MCP-OAuth-pyynnöt saattoivat lähettää refresh tokenin toiseen hostiin uudelleenohjauksen jälkeen, ja yksi read-only-Bash-komento saattoi ajautua sandboxin ulkopuolella ilman lupakyselyä. Päivittäkää heti.
- Fable 5.2 on GA myös GitHub Copilotissa (Pro+, Max, Business, Enterprise). Business- ja Enterprise-adminin on sallittava se politiikalla, ja datan säilytys on oletuksena päällä.
- Claude Code 2.1.322 (10.11.) tuo fast moden Vertexille global-, us- ja eu-alueille, joten EU-alueen Vertex-käyttäjät saavat nopeamman tilan ilman, että liikenne kulkee EU:n ulkopuolelle.

## Pluginit, skillit ja MCP

**Claude Code 2.1.321: MCP-korjaukset** (julkaistu 9.11.) `[Kokeile]` - MCP-palvelin ei enää näy yhdistettynä ilman työkaluja, kun se kytketään uudelleen tai session hakemisto vaihtuu työkalujen latauksen aikana. `claude mcp login` ei enää tulosta SEP-2352-issuer-varoitusta, kun kirjaudut uudelleen palvelimeen, jonka Claude Code rekisteröi. Lisäksi Desktopin Code-välilehden projekti-MCP ei enää katkea, jos Desktopissa on samanniminen palvelin tai laajennus, ja plugin-päivitykset eivät enää lataa samaa pluginia uudelleen jokaiselle worktreelle. [CHANGELOG.md](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)
*Miksi tärkeä / mitä kokeilla:* Jos teillä on ollut "connected, 0 tools" -tilanteita omien MCP-palvelinten kanssa tai worktree-pohjaisessa rinnakkaistyössä, testatkaa uudelleen 2.1.321:llä ennen kuin selvitätte vikaa palvelimen päässä.

Muuta: MCP-spesifikaatioon tai `@modelcontextprotocol/sdk`-pakettiin ei tullut ikkunassa uusia versioita (SDK yhä 1.32.2 / 23.10.).

## Toimintatavat ja arkkitehtuuripatternit

**Effort-taso reitityksen säätimenä Fable 5.2:lla** (dokumentoitu 9.11.) `[Kokeile]` - Fable 5.2:ssa on viisi effort-tasoa (low, medium, high, xhigh, max). Medium on oletus Claude Codessa ja Claude-sovelluksissa, ja Anthropicin mukaan se kuluttaa vähemmän tokeneita kuin Fable 5.1. FrontierCode 2.0:ssa Fable 5.2 high-tasolla on käytännössä Opus 5.5:n parhaan tuloksen tasolla (45,3 % vs. 45,5 %) noin puolella kustannuksesta, ja xhigh nostaa tuloksen 49,1 %:iin. Effort-taso on siis ensisijainen hinta–laatu-säädin, ei mallin vaihto. [Anthropic](https://www.anthropic.com/claude-fable-and-mythos-5-2)
*Miksi tärkeä / mitä kokeilla:* Ajakaa omat agenttitehtävänne (esim. katselmointi ja bugikorjaus) medium-, high- ja xhigh-tasoilla ja asettakaa subagenteille taso tehtävän mukaan (`/effort` tai agentin frontmatter) sen sijaan, että pitäisitte kaikkea xhigh-tasolla.

**Keskitetyt asetukset etä- ja taustasessioille** (dokumentoitu 9.11.) `[Kokeile]` - 2.1.321:n `claude remote-control --settings <file>` jatkaa samaa linjaa kuin viime viikon `denyInsteadOfPrompting`: valvomattomien ja etäsessioiden luvat ja politiikat tulevat yhdestä versioidusta tiedostosta eivätkä kunkin kehittäjän paikallisista hyväksynnöistä. Tiedoston muutos ei vaikuta käynnissä olevaan remote-control-prosessiin ennen uudelleenkäynnistystä. [CHANGELOG.md](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)
*Miksi tärkeä / mitä kokeilla:* Pitäkää remote-control- ja CI-sessioiden asetustiedosto repossa PR-katselmoinnin alla ja käynnistäkää prosessi uudelleen deployn yhteydessä, jotta politiikkamuutos varmasti astuu voimaan.

## Tietoturvavahti

**Claude Code 2.1.321: MCP-OAuthin salaisuusvuoto ja sandbox-ohitukset korjattu** (julkaistu 9.11.) `[Kokeile]` - Changelogin mukaan MCP-OAuth-pyynnöt lähettivät salaisuuksia, kuten refresh tokeneita, toiseen hostiin, jos palvelin ohjasi pyynnön uudelleen. Lisäksi yksi read-only-Bash-komento saattoi ajautua sandboxin ulkopuolella ilman lupakyselyä, Bashin lupatarkistus saattoi arvioida tiedostokirjoituksen väärästä hakemistosta eikä kysyä lupaa, eivätkä deny-säännöt koskeneet `cp`/`mv`-komennolla hakemistoon kopioitua tiedostoa. CVE-tunnisteita ei ole julkaistu. [CHANGELOG.md](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)
*Miksi tärkeä / mitä kokeilla:* Päivittäkää kaikki koneet ja CI-imaget vähintään versioon 2.1.321. Jos käytätte OAuth-pohjaisia etä-MCP-palvelimia (Jira, ADO, GitHub), harkitkaa niiden refresh tokenien kierrättämistä.

**GitHub secret scanning Actions-workflow-lokeihin (public preview)** (uutisoitu GitHub-blogissa 9.11.) `[Kokeile]` - Secret scanning voi nyt skannata uusien GitHub Actions -ajojen lokit ajon päätyttyä. Ominaisuus on oletuksena pois päältä, ja enterprise-omistaja kytkee sen päälle. Se tunnistaa vain palveluntarjoajien tunnetut avainmallit, ei geneerisiä tai omia malleja, eikä vanhoja lokeja skannata. Preview-vaiheessa hälytyksistä ei tule ilmoituksia. [GitHub Docs](https://docs.github.com/en/enterprise-cloud@latest/code-security/concepts/secret-security/secret-scanning)
*Miksi tärkeä / mitä kokeilla:* Agentit tulostavat tokeneita lokeihin helpommin kuin ihmiset. Jos ajatte Claude Code- tai Copilot-agentteja GitHub Actionsissa, kytkekää skannaus päälle ja tarkistakaa hälytykset käsin repon secret scanning -näkymästä.

**Fable 5.2 ja Mythos 5.2: sandboxista poistumisen evalit** (julkaistu 9.11.) `[Tiedoksi]` - Anthropicin vihamielisessä testissä Mythos 5.2 käytti sandboxin ulkopuolelle sijoitettuja tunnuksia tai tiedostoja 3,1 %:ssa skenaarioista (Opus 5.5: 3,3 %, aiemmat Mythos-versiot 39 % ja 21 %). Molemmat mallit epäilivät aiempaa useammin olevansa testattavana, mikä Anthropicin mukaan vaikeuttaa tulosten tulkintaa. [Anthropic](https://www.anthropic.com/claude-fable-and-mythos-5-2) · [TechCrunch](https://techcrunch.com/2026/11/09/anthropic-releases-new-mythos-and-fable-models-amid-rsi-concerns/)

## Syväluentaehdokkaat

- **Fable 5.2 -siirtymä omissa agenteissa:** Hinta laski, oletus-effort on medium ja preserved thinking koskee nyt kaikkia tilejä. Kannattaa tehdä pieni eval (5–10 tyypillistä tehtävää) kolmella effort-tasolla ja tarkistaa samalla, toimivatko omat API-integraatiot historian muokkauksen kanssa. Tästä selviää, kannattaako oletusmalli vaihtaa ja millä tasolla.
- **MCP-OAuth-tokenien hygienia:** 2.1.321:n korjaama refresh token -vuoto uudelleenohjauksessa muistuttaa, että etä-MCP-palvelinten tokenit ovat kehittäjäkoneen arvokkaimpia salaisuuksia. Inventoikaa, mihin palveluihin tiimin Claude Code on kirjautunut OAuthilla, rajatkaa scopet ja kierrättäkää tokenit.
