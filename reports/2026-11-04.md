## Kehitystyökalut ja agentit

**Claude Code 2.1.318** (julkaistu 3.11.) `[Kokeile]` - Laaja luotettavuusjulkaisu. `claude auth status` näyttää nyt tallennetun claude.ai-kirjautumisen päättymispäivän (`loginExpiresAt`), `claude -p` -JSON-tulokset sisältävät kentän `credential_expires_at`, ja tekstitulosteeseen tulee stderr-varoitus 10 päivää ennen vanhenemista. Korjauksia: `--continue` ei enää kadota aiempaa keskustelua virheellisen työkalukutsun jälkeen (regressio 2.1.314:ssä), `claude -p` ja Agent SDK eivät enää raportoi onnistumista, kun API-virhe katkaisi vastauksen, epäonnistuneet custom slash -komennot tulostavat nyt jotain headless-ajoissa, ja tyhjä tai rikkinäinen `NODE_EXTRA_CA_CERTS` ei enää kaada kaikkia yhteyksiä. Claude apps gatewayn `mantle`-upstreamit saivat `assume_role`-tuen AWS-tilien väliseen kustannusten kohdistamiseen. Lisäksi IDE-terminaalissa käynnistetty Claude Code ei enää asenna tai päivitä IDE-laajennusta automaattisesti. [CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md) · [npm](https://www.npmjs.com/package/@anthropic-ai/claude-code)
*Miksi tärkeä / mitä kokeilla:* Jos ADO-pipelinet ajavat `claude -p --output-format json`:ia claude.ai-tunnuksella, lue `credential_expires_at` ja nosta pipeline-varoitus, kun vanhenemiseen on alle viikko. Silloin yöajot eivät kaadu yllättäen `Not logged in` -virheeseen.

**Claude Code: auto moden `$defaults`-korjaus ajastetuille tehtäville** (julkaistu 3.11.) `[Kokeile]` - Virallisen changelog-sivun 3.11. merkinnän mukaan `autoMode.allow`-lista, josta puuttuu `"$defaults"`, ei enää poista ajastettujen tehtävien prompteja koskevaa sisäänrakennettua sääntöä. Samalla päivällä Claude Desktopin changelogiin merkittiin Monitor-työkalu Code-sessioihin: seurattavan komennon jokainen uusi tuloste-erä käynnistää uuden vuoron ilman käyttäjän syötettä. Desktop-merkintää ei pystytty varmistamaan toisesta lähteestä. [Claude Code changelog](https://code.claude.com/docs/en/changelog) · [Auto mode config](https://code.claude.com/docs/en/auto-mode-config)
*Miksi tärkeä / mitä kokeilla:* Jos olette määrittäneet oman `autoMode.allow`-listan tiedostoon `~/.claude/settings.json`, lisää listan alkuun `"$defaults"`. Muuten korvaat sisäänrakennetut poikkeukset sen sijaan, että laajentaisit niitä. Tarkista oletussäännöt komennolla `claude auto-mode defaults`.

[GitHub Changelog](https://github.blog/changelog/2026-11-03-github-copilot-is-now-available-in-jetbrains-air/) · [JetBrains Air -blogi](https://blog.jetbrains.com/air/category/news/)

## Pluginit, skillit ja MCP

**Claude Code 2.1.318: MCP- ja mod-muutokset** (julkaistu 3.11.) `[Kokeile]` - `claude mcp add` ja `remove` käyttävät nyt konfiguraation lukkoa: ne odottavat lukkoa tai palauttavat exit-koodin 1, kun aiemmin ne kirjoittivat tiedostoon ilman lukitusta. Stdio-MCP-palvelimia, jotka sulkeutuvat versiokyselyn jälkeen, ei enää kysellä joka käynnistyksessä. MCP-työkalun kutsu ennen työkalun latautumista palauttaa nyt työkalun input-skeeman. `/mcp` näyttää cloud-sessioissa vain mallin käytettävissä olevat työkalut. Modien `$.model.fork` sai `effort`-option, joten pienen sivutyön voi ajaa `low`-tasolla istunnon effortista riippumatta. `claude plugin validate` ei myöskään enää hyväksy custom-nimistä marketplace-tiedostoa, jonka `marketplace add` hylkää. [CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)
*Miksi tärkeä / mitä kokeilla:* Jos provisioitte MCP-palvelimia skripteillä rinnakkain, esimerkiksi devcontainerin `postCreateCommand`-vaiheessa, tarkista komentojen exit-koodit. Lukituksen takia ne voivat nyt epäonnistua näkyvästi eivätkä enää ylikirjoita toisiaan hiljaa.

## Toimintatavat ja arkkitehtuuripatternit

**MCP-palvelimet sallittujen listalta, ei agentin muistista** (dokumentoitu 2.–3.11.) `[Kokeile]` - Glow Labsin MCPhantom-havaintojen pohjalta Dark-Roast-Cyber on avannut detektiosääntöehdotuksen, joka hälyttää, kun agentti käynnistää tai konfiguroi arkistoidun MCP-referenssipalvelimen. Tällaisia ovat esimerkiksi `@modelcontextprotocol/server-puppeteer` sekä Python-paketit `mcp-server-sentry` ja `mcp-server-sqlite`, joita PyPI ei merkitse vanhentuneiksi. Pattern on yksinkertainen: agentti ei saa valita MCP-pakettia itse. Sallitut paketit ja versiot pidetään tiimin listalla, ja `.mcp.json`-muutokset tarkistetaan katselmoinnissa kuten riippuvuusmuutokset. [GitHub: telltale-detections #10](https://github.com/Dark-Roast-Cyber/telltale-detections/issues/10)
*Miksi tärkeä / mitä kokeilla:* Lisää CLAUDE.md:hen rivi "Älä asenna MCP-palvelimia; käytä vain .mcp.json:ssa listattuja" ja ADO:n PR-politiikkaan pakollinen katselmoija polulle `.mcp.json`. Korvaa arkistoitu Puppeteer-palvelin Playwright MCP:llä tai Chrome DevTools MCP:llä.

## Tietoturvavahti

**MCPhantom: koodausagentit asentavat arkistoituja MCP-palvelimia** (julkaistu 2.11., uutisoitu 3.11.) `[Kokeile]` - Glow Labsin mukaan Claude Code, Cursor, Codex CLI ja Claude Cowork asentavat esimerkiksi pyynnöstä "lisää GitHub MCP" Anthropicin vanhoja, arkistoituja referenssipalvelimia, joita ne muistavat koulutusdatasta. Näihin palvelimiin ei enää tule tietoturvakorjauksia. Toissijaisen yhteenvedon mukaan arkistoitu referenssipaketti löytyi 98 %:sta sessioista, joissa asennettiin vanhentunut MCP-palvelin. Help Net Securityn mukaan vakavin löydös on prompt injectionilla laukaistava etäkoodin suoritus Puppeteer-palvelimessa. CVE-tunnusta ei ole ilmoitettu, eikä RCE:n yksityiskohtia pystytty varmistamaan primäärilähteestä. [Help Net Security](https://www.helpnetsecurity.com/2026/11/03/mcphantom-deprecated-mcp-servers/) · [Detektioehdotus](https://github.com/Dark-Roast-Cyber/telltale-detections/issues/10)
*Miksi tärkeä / mitä kokeilla:* Aja kehittäjäkoneilla ja repoissa `grep -rE "server-(puppeteer|github|gdrive|slack)|mcp-server-(sentry|sqlite)" ~/.claude.json .mcp.json` ja korvaa osumat ylläpidetyillä palvelimilla, esimerkiksi GitHubin virallisella `github-mcp-server`:llä.

## Syväluentaehdokkaat

- **MCP-palvelinten inventaario ja sallittujen lista:** MCPhantom osoittaa, että agentti voi itse tuoda ympäristöön ylläpitämättömän ja haavoittuvan komponentin, eikä kukaan huomaa sitä. Käykää läpi kaikkien kehittäjien ja CI-agenttien MCP-konfiguraatiot ja kirjatkaa hyväksytyt palvelimet. Selvittäkää myös, voiko Claude Coden managed settingsillä rajata sallitut MCP-palvelimet organisaatiotasolla.
- **Headless-ajojen tunnistautumisen elinkaari:** 2.1.318:n `credential_expires_at` ja `loginExpiresAt` mahdollistavat ennakoivan valvonnan. Tarkistakaa samalla, kannattaisiko CI-ajot siirtää claude.ai-kirjautumisesta `setup-token`- tai API-avainpohjaisiksi, jotta yöajot eivät riipu yksittäisen kehittäjän sessiosta.
