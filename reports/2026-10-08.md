## Uudet mallit ja versiot

**Claude Haiku 5.5 – tiered pricing, 90 % hintalasku pienissä pyynnöissä, adjustable effort, subagent-käyttöön optimoitu (Anthropic, julk. 7.10.2026)**

Anthropic julkaisi Claude Haiku 5.5:n 7.10.2026. Merkittävin uutuus on tiered pricing -rakenne jota ei aiemmissa Claude-malleissa ole: pyynöt ≤100 000 tokenia hinnoitellaan $0,10/MTok input, $0,50/MTok output; pyynöt >100 000 tokenia $0,50/MTok input, $2,50/MTok output. Vertailu Haiku 4.5:een ($1/$5/MTok): pienet pyynöt 90 % halvempia, suuret pyynöt 50 % halvempia. Haiku 5.5 on ensimmäinen Haiku-luokan malli, jolla on adjustable effort -asetus: kehittäjä voi säätää päättelysyvyyttä kutsutasolla. Samalla Anthropic ilmoitti Sonnet 5.5:n cache-read-hinnan laskusta ja API-krediiteistä Claude Max- ja Team-tilaajille. Saatavuus: Claude Platform, AWS, GCP, Azure; model ID: `claude-haiku-5-5`.

Anthropic asemoi Haiku 5.5:n halvimpana, nopeimpana ja kykyisimpänä pienmallinaan – tarkoitettu erityisesti massavolyymitiloihin kuten yhteenvetoon, tietokantakyselyihin, luokitteluun ja subagenteina laajemmissa agenttiarkkitehtuuriissa. Yhdistetty Opus 5.5:n (reasoning) tai Sonnet 5.5:n (koodaus) kanssa Haiku 5.5 toimii ensimmäisenä "sorminahkamallin" kerroksena tiimin agenttityönkuluissa.

*Miksi tärkeä / mitä kokeilla:* Tier 1 -hinnoittelu ($0,10/$0,50) tekee Haikusta GPT-6 Lunan ($0,10/$0,50) suoran kilpailijan – ensimmäistä kertaa Anthropicin halvin malli on hintapariteettitasolla halvimman OpenAI:n frontier-pienmallin kanssa. Subagent-agenttiarkkitehtuuriissa jossa Haiku hoitaa toistuvat tehtävät (tietokantahaut, muistihaut, lyhyet yhteenvedot), tier 1 -hinnoittelu voi laskea kokonaisagenttikustannuksia merkittävästi. Testaa: korvaa Claude Sonnet 5.5 -subagentti Haiku 5.5:llä kaikissa pyynnöissä ≤100 k tokenia ja mittaa kustannusero viikon agenttikäytöstä.

## Repot ja yhteisön tekniikat (mitä kokeilla)

**morluto/rea – MCP+CLI-työkalu coding-agenteille minkä tahansa ohjelmiston reverse engineeringiin; Hopper-native, Evidence v2, 8 459 tähteä (GitHub trending #1 Oct 7, 2026)**

REA ("Reverse Engineer Anything") on TypeScript-pohjainen MCP-server ja CLI joka antaa coding-agentille kykyä reverse engineerata minkä tahansa ohjelmiston ilman manuaalista tool-vaihtoa. Tämänhetkiset kyvykkyydet: syväanalytiikka Hopper-disassemblerin kautta, täydelliset function dossierit, toistettavat Evidence v2 -tietueet (jokainen löydös viitteineen) ja kontrolloitu process capture. Agentti voi tutkia binääriohjelman toimintaa ja palauttaa struktuoidun evidenssiraportin. Roadmap kattaa packaged apps, JavaScript-bundlet, verkkosivut, API:t, protokollat, mobiili- ja firmware-artefaktit sekä versioiden väliset muutosanalyysit. Asennus: `npx skills add morluto/rea` tai `npm install --global rea-agents && rea setup`. MIT-lisenssi, Node.js 24+.

*Miksi tärkeä / mitä kokeilla:* REA ratkaisee konkreettisen ongelman: agentti ei tähän asti pystynyt navigoimaan reverse engineering -prosessia johdonmukaisesti (Hopper → disassembly → funktioanalyysi → evidenssi) ilman käsin rakennettua workflow-putkilinjaa. Kokeile: anna Claude Code -agentille binääri jonka käyttäytymistä et tunne ja pyydä REA:lla tuottamaan function dossier – vertaa tuloksen syvyyttä manuaaliseen Hopper-analyysiin.

**VectifyAI/PageIndex – vectorless reasoning-based RAG, puuhakemisto + LLM-navigointi, MCP server, 38 000+ tähteä (GitHub trending Oct 8, 2026; julk. alkuperäisesti toukokuu 2026)**

PageIndex korvaa vector-tietokannan ja chunking-lähestymistavan hierarkkisella puuhakemistolla jota LLM navigoi reasoning-ketjulla. Käytännössä: dokumentit indeksoidaan luonnollisen rakenteen (osiot, kappaleet) mukaan – ei pilkota kiinteiksi paloiksi. Retrieval tapahtuu LLM-navigointina: malli tekee "tree search" hakutuloksen löytämiseksi samaan tapaan kuin ihmisasiantuntija selaa kirjaa. Ei vector DB -riippuvuutta, ei upotusmallin valinnan ongelmaa. Uudet ominaisuudet: PageIndex Flash (nopeampi indeksointi, oletuksena teksti-PDF:ille), PageIndex File System (tiedostotason puuhakemisto koko korpukselle), local mode (pip, oma LLM-avain) sekä nyt MCP server (`VectifyAI/pageindex-mcp`) joka tekee PageIndexistä suoran Claude Code - ja Cursor-yhteensopivan tiedonhakutyökalun. Python, MIT, 38 000+ tähteä, 3 000+ forkia.

*Miksi tärkeä / mitä kokeilla:* Useimmat RAG-toteutukset kärsivät chunkingin aiheuttamasta kontekstikatkeamisesta. PageIndex eliminoi tämän käyttämällä dokumentin omaa rakennetta. MCP server -tuki tarkoittaa nyt, että Claude Code pystyy hakemaan tietoa PageIndex-indeksistä suoraan ilman välityspalvelinta. Testaa: rakenna PageIndex-indeksi projektiisi liittyvästä teknisestä dokumentaatiosta (PDF-spesifikaatiot, sisäinen wiki) ja vertaa hakutulosten tarkkuutta Chroma- tai pgvector-pohjaiseen RAGiin etenkin pitkissä dokumenteissa.
