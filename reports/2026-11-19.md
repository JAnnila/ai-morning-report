# AI-aamuraportti - 2026-11-19

## Päivän tärkeimmät

- Claude Code 2.1.328 lisäsi `mcp_tool`-hookeille asetuksen `"onFailure": "block"` ja korjasi kaksi bugia, jotka saattoivat tyhjentää tai poistaa projektin ajastettuja tehtäviä; lisäksi Code Modeen tuli kymmenkunta korjausta.
- GitHub Copilotin team customizations tuli yleisesti saataville: tiimin ylläpitäjä voi asettaa hyväksytyt Agent Pluginit tiimin oletuksiksi VS Codeen, Copilot-sovellukseen ja Copilot CLI:hin.
- Googlen Gemini 4 Neon julkaistiin Gemini API:ssa ja tuli samana päivänä yleisesti saataville GitHub Copilotiin; Google lupaa Carbonin tasoista laatua pienemmällä tehtäväkohtaisella tokenikulutuksella.
- Foundry Agent Servicen Ignite-julkaisuissa hosted agenttien verkkoliikenteen rajaus (egress) ja pitkien ajojen palautus tulivat yleisesti saataville; Azure Policy -hallinta egressille on public previewssä.
- "External sandbox" -pattern (Prime Radiant, Simon Willison): agentti ajaa koneellasi, mutta sen suorittamat komennot ajetaan erillisessä VM:ssä tai kontissa allow-list-proxyn ja tunnisteiden korvauksen kanssa. Valmiit prototyypit Claude Codelle ja Codexille.

## Kehitystyökalut ja agentit

**Claude Code 2.1.328** (julkaistu 18.11.) `[Kokeile]` - Uusia ominaisuuksia:
- Auto mode Opus 4.6:lle ja Sonnet 4.6:lle Bedrockissa, Google Cloudin Agent Platformissa, Microsoft Foundryssa ja Claude apps gatewayssa. Interaktiiviset sessiot ilman asetettua lupatilaa käynnistyvät siinä.
- `/status` ja `claude doctor` varoittavat, jos OpenTelemetry-exporterilla ei ole endpointia.
- `CLAUDE_CODE_DISABLE_DEFERRED_TOOL_RESUME` estää `claude -p --resume`/`--continue`-ajoa suorittamasta hookin lykkäämää työkalukutsua.
- Self-hosted runneriin useita lisäyksiä, kuten `--repository-folder`, `--hook-label` ja uudet orkestraattorin metriikat.

Tärkeimmät korjaukset:
- Ajastetun tehtävän tallennus ei enää tyhjennä projektin muita tehtäviä, kun tehtävätiedostoa ei voida lukea, eikä kirjoitusvirheellinen tehtävä enää poistu seuraavassa tallennuksessa.
- Automaattinen tiivistys rakentaa nyt system promptin uudelleen kuten `/compact`, eikä käytä vanhaa.
- zsh:ssa `=`-alkuiset sanat (esim. `[ a == b ]`) eivät enää kaada Bash-komentoja.
- Code Modeen kymmenkunta korjausta, mm. skriptit eivät enää pysähdy 10 minuutin auki olleeseen lupakyselyyn, ja lukuoikeuksin ajetuille subagenteille ei enää tarjota `write()`- ja `edit()`-funktioita.
- Korjattu 2.1.327:n regressio, jossa subagentin effort-taso kytkeytyi pois Bedrockissa, Agent Platformissa tai Foundryssa.

Claude Agent SDK 0.3.328 julkaistiin samana päivänä. [CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md) · [npm](https://www.npmjs.com/package/@anthropic-ai/claude-code?activeTab=versions)
*Miksi tärkeä / mitä kokeilla:* Ajakaa `claude update`. Jos käytätte Claude Codea Foundryn kautta Opus 4.6:lla, tarkistakaa, että interaktiiviset sessiot käynnistyvät nyt auto modessa; jos ette halua sitä, asettakaa `disableAutoMode` hallittuihin asetuksiin.

**Foundry Agent Service: egress-rajaus ja pitkien ajojen palautus GA** (julkaistu 18.11.) `[Kokeile]` - Ignite-julkaisut hosted agenteille:
- Verkkoliikenteen rajaus (egress) on yleisesti saatavilla. Sallitut kohteet määritetään, ja rajaus toteutetaan agentin sandboxin ulkopuolella. Liikenne kannattaa ensin auditoida ja rakentaa allow-list todellisesta käytöstä.
- Azure Policy -hallinta egressille on public previewssä: sallitut egress-määritykset voi vaatia tilaus- tai resurssiryhmätasolla ja estää poikkeavat muutokset.
- Pitkien ajojen palautus kaatumisen, uudelleenkäynnistyksen tai uudelleenjulkaisun jälkeen on GA. Palautus ajaa handlerin uudelleen, joten edistyminen pitää tallentaa ja sivuvaikutukset tehdä idempotenteiksi. Idle timeout on säädettävissä 2 minuutista 4 tuntiin (oletus 15 min).
- Lisäksi julkaistiin mm. ulkoiset agentit GA, voice agentit GA ja yksityisen CA:n luottamus (public preview).

[Microsoft Foundry -blogi](https://devblogs.microsoft.com/foundry/whats-new-in-foundry-agent-service-at-ignite-2026/) · [Egress-ohje](https://devblogs.microsoft.com/foundry/egress-controls-hosted-agent/) · [External agents GA](https://techcommunity.microsoft.com/blog/azure-ai-foundry-blog/external-agents-in-microsoft-foundry-are-now-generally-available/4572630)
*Miksi tärkeä / mitä kokeilla:* Jos ajatte agentteja Foundryssa, kytkekää egress ensin audit-tilaan ja muuttakaa allow-list enforce-tilaan viikon datan perusteella. Agent Framework -kaappauksen kaltaisessa tilanteessa rajaus olisi estänyt tunnisteiden lähetyksen hyökkääjän webhookiin.

## Pluginit, skillit ja MCP

**Claude Code 2.1.328: MCP-hookit ja skeemakorjaukset** (julkaistu 18.11.) `[Kokeile]` - `mcp_tool`-tyyppiset hookit tukevat nyt `"onFailure": "block"` -asetusta kuten command- ja HTTP-hookit: jos hookin kutsu epäonnistuu, toiminto estetään. Lisäksi korjattiin MCP-työkalut, joiden input-skeema alkaa `anyOf`-, `oneOf`- tai `allOf`-avaimella ja jotka katosivat kolmannen osapuolen pilvissä tai telemetrian ollessa pois päältä. Virheellisellä skeemalla oleva MCP-työkalu jätetään nyt pois ja Claudelle kerrotaan syy, sen sijaan että koko pyyntö epäonnistuisi. [CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)
*Miksi tärkeä / mitä kokeilla:* Jos teillä on MCP-palvelimeen perustuva tarkistushook (esim. politiikka- tai salaisuustarkistus), lisätkää siihen `"onFailure": "block"`, jotta palvelimen kaatuminen ei ohita tarkistusta hiljaa.

**Copilotiin kahdeksan uutta GitHub-verified MCP-connectoria** (julkaistu 18.11.) `[Seuraa]` - GitHub lisäsi public previewssä olevaan connector-ohjelmaan kahdeksan palvelua, mm. Business- ja Enterprise-käyttäjille ylläpitäjän pitää ensin sallia Editor preview features -politiikka, eivätkä connectorit vielä toimi GitHub Actionsissa ajettavissa sessioissa. [GitHub Changelog](https://github.blog/changelog/2026-11-18-connect-supabase-box-calendly-and-more-to-copilot/) · [Docs](https://docs.github.com/en/copilot/concepts/customizations/copilot-connectors)

## Toimintatavat ja arkkitehtuuripatternit

**External sandbox -pattern koodausagenteille** (julkaistu 16.11., uutisoitu 17.11.) `[Kokeile]` - Prime Radiantin kirjoitus kuvaa mallin, jossa agentti (Claude Code, Codex tai Pi) ajaa omalla koneella, mutta sen suorittamat komennot ajetaan erillisessä sandboxissa. Mukana on kolme prototyyppiä: v86 (Alpine Linux WebAssemblyssä), Apple Containers ja Microsoftin Quicksand (QEMU + Alpine). Sandboxeissa on valinnainen HTTP/HTTPS-allow-list-proxy ja tunnisteiden korvausmekanismi, jolla autentikoidut API-kutsut onnistuvat ilman, että salaisuus näkyy agentille. Simon Willison nosti kirjoituksen esiin ja perusteli sitä erityisesti paikallisten mallien ja prompt injectionin riskeillä. [Prime Radiant](https://blog.primeradiant.com/external-sandboxes-for-coding-agents/) · [Simon Willison](https://simonwillison.net/2026/Nov/17/external-sandboxes-for-coding-agents/)
*Miksi tärkeä / mitä kokeilla:* Sama periaate kuin Foundryn egress-rajauksessa ja Claude Coden sandboxissa, mutta paikallisesti: tunnisteet eivät ole agentin ympäristössä lainkaan. Verratkaa tiimin nykyiseen sandbox-asetukseen, erityisesti jos agentti käsittelee ulkoista sisältöä (issuet, PR-kommentit, web).

**Pitkäkestoisten agenttiajojen idempotenssi Foundryn palautusmallissa** (julkaistu 18.11.) `[Tiedoksi]` - Foundryn pitkien ajojen palautus ajaa handlerin kokonaan uudelleen kaatumisen jälkeen, joten Microsoft ohjeistaa tallentamaan edistymisen checkpointeihin ja estämään sivuvaikutusten (PR:n avaus, work itemin luonti, viestit) toistumisen. [Microsoft Foundry -blogi](https://devblogs.microsoft.com/foundry/whats-new-in-foundry-agent-service-at-ignite-2026/)
*Miksi tärkeä / mitä kokeilla:* Sama periaate pätee ajastettuihin Claude Code -rutiineihin: tarkistakaa ennen sivuvaikutusta, onko se jo tehty (esim. onko haaralle jo PR tai onko päivän raporttitiedosto jo commitoitu).

Muuta: 7 vuorokauden ikkunasta (12.–19.11.) löytyi lisäksi vain evaleja ja harness engineeringiä käsitteleviä yleiskatsauksia, joissa ei ollut uutta tekniikkaa. LangChainin context engineering -kirjoitukset (2.11. ja ~10.11.) ovat ikkunan rajalla tai sen ulkopuolella.

## Syväluentaehdokkaat

- **Agentin suorituksen eristäminen tunnisteista:** External sandbox -pattern, Foundryn egress-rajaus ja eilinen `agent-framework`-kaappaus osoittavat samaan suuntaan: agentin ajamat komennot eivät saisi nähdä Azure-, ADO- tai GitHub-tunnisteita, ja ulosmenevä liikenne pitäisi rajata. Käykää läpi, missä tiimin agentit (paikallinen Claude Code, CI-ajot, Foundry) ajavat koodia samassa ympäristössä kuin tunnisteet, ja kokeilkaa yhtä ratkaisua: Prime Radiantin prototyyppiä paikallisesti tai Foundryn egress-auditointia pilvessä.
- **Pluginien jakelu tiimille sekä Claude Codessa että Copilotissa:** Copilotin team customizations GA ja stitch-skills-repon rakenne näyttävät, miten sama Agent Skills -standardin mukainen plugin voidaan jakaa molempiin työkaluihin. Selvittäkää, voiko tiimin omat skillit ja Azure DevOps -MCP-määritykset pitää yhdessä GitHub-repossa, josta ne jaetaan sekä Claude Coden plugin-markkinapaikkana että Copilotin tiimioletuksena.
