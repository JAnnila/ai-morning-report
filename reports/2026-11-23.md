## Pluginit, skillit ja MCP

**Claude Code 2.1.330: MCP-, plugin- ja mod-muutokset** (julkaistu 20.11.) `[Kokeile]` - MCP:n ja pluginien kannalta olennaiset muutokset:
- Uusi sisäänrakennettu mod **easel** piirtää kaavioita pyydettäessä ja MCP-metriikkatulosten alle (Pro, Max ja soveltuvin osin Team/Enterprise, macOS ja Linux). Automaattiset kaaviot voi kytkeä pois `/config`-asetuksista. Jos MCP-allowlist sulkee easelin pois, se pysyy estettynä, mutta turha varoitus jokaisessa käynnistyksessä poistui.
- Alagentin määrittelemää MCP-palvelinta ei enää sammuteta, kun yksi alagentti lopettaa ja muut vielä käyttävät palvelinta.
- Kun monen MCP-työkalun syöteskeema on API:n hylkäämä, vuorot eivät enää kaadu "JSON schema is invalid" -virheeseen eikä sessiotiedosto kasva megatavuittain.
- `/mcp` ryhmittelee palvelimet: pluginien palvelimet ovat "Plugin MCPs" -otsikon alla, `--mcp-config`-palvelimet ja sisäänrakennetut "Other MCPs" -otsikon alla, ja palvelimen sivu kertoo, mihin pluginiin se kuuluu.
- `claude plugin install --json` palauttaa nyt `commandPrinted`- ja `commandFailed`-kentät.
- Rinnakkaiset `claude plugin` -komennot eivät enää hukkaa asennettuja plugineja.

[CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)
*Miksi tärkeä / mitä kokeilla:* Jos asennatte tiimin plugineja skriptillä tai CI:ssä, lukekaa `claude plugin install --json` -tuloksesta `commandFailed` ja failatkaa ajo sen perusteella. Tarkistakaa samalla `/mcp`-näkymästä, mitkä palvelimet tulevat plugineista.

Muuta: `@modelcontextprotocol/sdk` on yhä 1.32.2 (23.10.), eikä MCP-spesifikaatioon tullut muutoksia. OpenAI Agents SDK (0.22.0) ja LangGraph (1.7.5) eivät julkaisseet uutta. Vercel AI SDK julkaisi rutiinipäivitykset 7.0.179 (20.11.) ja 6.0.336 (22.11.).

## Toimintatavat ja arkkitehtuuripatternit

**How the Claude Code team thinks about verification** (julkaistu 16.11.) `[Kokeile]` - Addy Osmanin kirjoitus siitä, miten Claude Code -tiimi varmistaa koodin, josta noin 90 % on Clauden kirjoittamaa ja katselmoimaa:
- Claude ajaa testit, buildin ja linterin ennen PR:n avaamista.
- Repon `.claude/skills/`-kansiossa on verify-skill, jonka Claude ajaa ennen committia. Tiimi pyytää Claudea myös stressitestaamaan itse skillin.
- Muutoksia portittavat säännöt ovat haarassa, jota muutos ei voi muokata, joten agentti ei voi "pelata" sääntöjä.
- Jokaiseen commitiin leimataan varmistuksen tyyppi, myös arvo "none", joten varmistamattomat commitit löytyvät jälkikäteen.
- Kolmen epäonnistuneen korjausyrityksen jälkeen agentti pysäytetään ja ihminen otetaan mukaan.
- Käytössä on 39 kohdan luotettavuustarkistuslista, jossa jokaisella kohdalla on diffistä näkyvä laukaisin, tarkistus ja sen taustalla olleet incidentit.

[claude.dev](https://claude.dev/blog/how-the-claude-code-team-thinks-about-verification/)
*Miksi tärkeä / mitä kokeilla:* Luokaa reposta `.claude/skills/verify/SKILL.md`, joka ajaa `dotnet build && dotnet test` ja `ng lint && ng test --watch=false`. Lisätkää commit-viestiin trailer (esim. `Verified-By: tests|manual|none`) ja Stop-hook, joka pysäyttää agentin kolmannen epäonnistuneen yrityksen jälkeen.

**Agent Host Protocol: agenttisessiot, jotka jatkuvat laitteelta toiselle** (julkaistu 17.11.) `[Tiedoksi]` - GitHubin insinööriblogi kuvaa avoimen Agent Host Protocolin (AHP). Sen avulla agenttisessio voi alkaa VS Codessa ja jatkua Copilot-sovelluksessa, mobiilissa tai cloud sandboxissa. Agent host on erillinen prosessi, joten työ voi jatkua, vaikka editori-ikkuna suljetaan. GitHubilla on kaksi itsenäistä toteutusta (TypeScript VS Codessa, Rust pilvessä), ja kolmannet osapuolet voivat rakentaa omia asiakkaitaan protokollan päälle. [GitHub Blog](https://github.blog/engineering/engineering-principles/building-the-agent-host-protocol-for-sessions-that-continue-across-devices/)
*Miksi tärkeä / mitä kokeilla:* Jos tiimi käyttää rinnakkain Claude Codea ja Copilotia, verratkaa AHP:n arkkitehtuuria (erillinen host-prosessi) Claude Coden Remote Controliin ja self-hosted runneriin, kun valitsette pitkien agenttiajojen ajoympäristöä. Kokeilu: `code agent host --github-environment` projektikansiossa.

## Tietoturvavahti

**Dragos: kolmen AI-inferenssipalveluntarjoajan sisällä luettiin asiakkaiden kehotteita; OpenRouter poisti tarjoajat** (OpenRouterin toimet 22.11.) `[Kokeile]` - Dragos syötti heinä–marraskuussa noin kaksi miljoonaa kehotetta, joissa oli yksilöllisiä URL-osoitteita ja canary-tunnisteita (mm. AWS-avaimia). Sen jälkeen se seurasi, missä ne ilmaantuivat uudelleen. Tulokset:
- Ainakin kolmen palveluntarjoajan data oli hyökkääjien käsissä: kehotteiden tunnisteilla yritettiin päästä Dragosin testijärjestelmiin ja AWS-tileille.
- Hyökkääjät kopioivat myös samoilla palvelimilla ajettuja oikeiden asiakkaiden pyyntöjä, myös ZDR-merkittyjä.
- Markkinapaikan kautta toimivat jälleenmyyjät pystyivät näkemään ja säilyttämään kehotteita tavallisella lokituksella, ilman haavoittuvuuden hyväksikäyttöä.

OpenRouter poisti kolme palveluntarjoajaa, otti 125 endpointilta ZDR-kelpoisuuden pois ja ilmoitti asiakkaille. Sen mukaan sen omia järjestelmiä ei murrettu. Tarjoajia ei ole nimetty. [Dragos](https://www.dragos.com/blog/ai-supply-chain-security-canary-tokens) · [Unite.AI](https://www.unite.ai/openrouter-cuts-three-providers-after-ai-prompt-exposure-findings/)
*Miksi tärkeä / mitä kokeilla:* Agentit vievät tiedostojen sisältöä, `.env`-arvoja ja työkalutuloksia kehotteisiin. Jos jokin tiimin työkalu tai agentti reitittää malleja aggregaattorin kautta, rajatkaa se tunnettuihin palveluntarjoajiin (provider allowlist) ja kierrättäkää salaisuudet, jotka ovat voineet päätyä kehotteisiin. Pitkällä aikavälillä kannattaa suosia suoraa sopimussuhdetta (Anthropic API, Azure Foundry, Bedrock).

**AI-agentit löysivät MONAI Labelista nollapäivän: CVE-2026-133968** (raportoitu 20.11., korjaus 0.8.6 22.11.) `[Tiedoksi]` - Amazon Threat Intelligencen mukaan Kiinaan kytkeytyvä toimija käytti Cairn-agenttikehystä. Agentit kartoittivat MONAI Labelin API:n ja löysivät noin 11 minuutissa path traversal -haavoittuvuuden `PUT /datastore/image` -endpointin image-kentästä. Myöhemmässä sessiossa ne saivat sen avulla root-shellin yliopiston palvelimelle, ja operaattorin antaman proxyn kautta ne pääsivät toiseen verkkoon, jossa ajettiin samaa ohjelmistoa. Haavoittuvia ovat versiot 0.8.5 asti; autentikointi on oletuksena pois päältä. [SecurityOnline](https://securityonline.info/monai-label-zero-day-cve-2026-133968/) · [Gridinsoft](https://blog.gridinsoft.com/cairn-ai-agents-monai-label-zero-day/)
*Miksi tärkeä / mitä kokeilla:* Esimerkki siitä, että agenttipohjainen hyökkääjä löytää ja hyödyntää tunnistautumattoman sisäisen API:n minuuteissa. Käykää läpi tiimin julkisesti tai VPN:n takaa näkyvät dev- ja preview-ympäristöt (esim. Azure App Servicen staging-slotit), joissa autentikointi on pois päältä.

Muuta: Visual Studion Copilotin `.mcp.json`-ohitus (CVE-2026-103572) ja opencoden MCP-OAuth-RCE kiersivät viikon tietoturvakoosteissa, mutta molemmat korjattiin jo loka-syyskuussa. Varmistakaa silti, että Visual Studio on vähintään 17.14.42 tai 18.10.4.

## Syväluentaehdokkaat

- **Verifiointisilmukka tiimin repoihin:** Claude Code -tiimin kirjoitus on konkreettisin tähän mennessä julkaistu kuvaus siitä, miten agentin koodi varmistetaan tuotantotasolla (verify-skill, suojattu sääntöhaara, commit-leimat, kolmen yrityksen raja). Rakentakaa yhteen .NET- tai Angular-repoon verify-skill ja commit-trailer, ja mitatkaa kahden viikon ajan, kuinka moni agentin commit menee läpi ilman ihmisen korjausta.
- **Mallikutsujen toimitusketju:** Dragosin tulokset osoittavat, että ZDR-lupaus ei suojaa, jos inferenssipalvelu itse on murrettu. Kartoittakaa, minkä palveluntarjoajien kautta tiimin agenttien, CI:n ja omien työkalujen kehotteet kulkevat (Claude Code, Copilot, mahdolliset aggregaattorit, OpenRouter-pohjaiset työkalut). Pitäkää salaisuudet poissa kehotteista (deny-säännöt `.env`-tiedostoille, salaisuuksien skannaus hookissa).
