## Uudet mallit ja versiot

**Seurantapäivitys: GLM-5.3 (743B) avoimet painot – ei julkaistu sovitusti 28.8.2026 (Z.ai)**

Z.ai lupasi GLM-5.3:n avoimet painot noin kaksi viikkoa API-julkaisun (14.8.2026) jälkeen eli ~28.8. Päivä tuli ja meni ilman julkaisua – `zai-org/GLM-5.3` HuggingFacessa näyttää edelleen "Upcoming release" -statuksen. Syy: malli saavutti odottamattoman korkean 84,5 % pistemäärän CyberGym-haavoittuvuuksien löytämistestissä (marginaalisesti yli Claude Mythos 5:n ja GPT-5.6 Solin), ja Z.ai jatkaa turvallisuusarviointia ilman uutta julkaisupäivää.

Muistutus teknisistä tiedoista: 744B kokonaisparametrit / ~40B aktiivista per token (MoE), 200K konteksti, koodaus- ja kyberturvallisuusspesialisti. Painot ~1,5 TB BF16:ssa (~750 GB FP8:ssa).

*Miksi tärkeä / mitä kokeilla:* Seuraa `zai-org` HuggingFace-profiilia. Kun painot julkaistaan, tarkista ensin lisenssi (Apache 2.0 oletettu mutta ei vahvistettu) ja Z.ai:n turvallisuusraportti ennen tuotantokäyttöä – erityisesti kyberturvallisuustyönkuluissa viivästys kertoo, että mallin hyökkäyskyky on merkittävä.

**VoiceMem: Streaming Dual-Brain Memory for Real-Time Interaction (arXiv 2608.26005, julk. 26.8.2026, HF trending 27.–28.8.2026)**

NTU Singaporen, NUSin ja Tsinghuan tutkijat julkaisivat 26.8. VoiceMem-arkkitehtuurin, joka nousi Hugging Facen trendaavaksi paperiksi 27.–28.8. VoiceMem ratkaisee pitkäaikaisen pullonkaulan puhemallien kehittämisessä: tarkka ja emotionaalisesti personoitu pitkäkestoinen muisti ilman latenssipenaltia.

**Arkkitehtuuri:** rinnakkainen **vasen aivopuolisko** (informatiivinen haku faktamuistiin) ja **oikea aivopuolisko** (emotionaalinen personalisaatio) + streaming I/O -mekanismi. Kumpikin puolisko toimii rinnakkain – ei peräkkäin.

**Tulokset:** vasen puolisko päihitti Mem0:n top-200-haun top-5-haullaan lähes 30 pisteellä; oikea puolisko johti kolmea eri persona-benchmarkia (+4,29 pistettä edelliseen SOTA:aan nähden). Kriittisin numero: **134 ms hakuaika** – selvästi alle VAD-latenssin, eli järjestelmä lisää nolla havaittavaa latenssia käyttäjälle.

*Miksi tärkeä / mitä kokeilla:* VoiceMem on ensimmäinen julkinen toteutus joka yhdistää faktamuistin ja tunnemuistin streaming-puhemalliin ilman latenssioffsetia. Relevantti kaikille jotka rakentavat pitkäkestoisia puheagentteja (asiakaspalvelurobotit, kokousassistentit, henkilökohtaiset avustajat). Arkkitehtuuri on myös sovellettavissa muihin multimodaalisiin järjestelmiin – dual-brain -rakenne ei ole sidottu pelkästään puheeseen.

[arXiv: VoiceMem 2608.26005](https://arxiv.org/abs/2608.26005)

## Repot ja yhteisön tekniikat (mitä kokeilla)

**DeepSeek Harness: 200 000 GitHub-tähteä 27.8. – "Everything is a Plugin" -agenttiajoympäristö (DeepSeek AI, julk. 13.8.2026, milestone 27.8.2026)**

DeepSeek Harness (`deepseek-ai/deepseek-harness`) ylitti 200 000 GitHub-tähden rajan 27.8. – yksi nopeimmista kasvukäyristä kehittäjätyökaluissa (95 000 tähteä kahdessa päivässä julkaisun jälkeen 13.8., 200k kahden viikon kuluttua). Projekti on nyt aktiivisimmin kasvava AI-agenttirepositorio GitHubissa tähtinopeuden perusteella.

**Arkkitehtuuriperiaate:** malliadapteri, työkalu-registry, istuntoloki ja agenttiehdotusilmaus ovat kaikki vaihdettavia plugineja. Tämä tekee Harnessista käytännöllisesti katsoen malli-agnostisen agenttiajoympäristön – voit korvata DeepSeekin Claudella, GPT-5.6:lla tai millä tahansa muulla mallilla vain vaihtamalla adapteria.

Uusin julkaisu v0.1.1-rc.2 (21.8.): lisätty DeepSeek V4 Flash Vision -polku, Files API -kuvan uudelleenkäyttö, automaattinen kuvien esikäsittely; korjattu Bubblewrap /proc/<pid>/root escape route (turvallisuuskorjaus).

*Miksi tärkeä / mitä kokeilla:* Jos rakennat koodausagenttia, Harness on selvimpien avoimen lähdekoodin vaihtoehto Claude Codelle. Plugin-arkkitehtuuri on erityisen kiinnostava A/B-testaukseen eri mallien välillä täsmälleen samassa työnkulussa – vaihda vain `model-adapter`-plugin. Aloita `docs/plugin-authoring.md`-dokumentaatiosta.

**Claude Code v2.1.247: MCP 2026-07-28 -protokollatuki ja remote MCP -uudelleenyhteyskorjaus (Anthropic, julk. 26.8.2026)**

Anthropic julkaisi Claude Code v2.1.247:n 26.8. Merkittävimmät muutokset kehittäjille:

- **MCP 2026-07-28 -protokollatuki**: tuki MCP:n viidennelle spesifikaatiolle – stateless core, vahvistettu OAuth/OIDC-autorisointi, versioitu Apps- ja Tasks-laajennus. Suurin protokollapäivitys sitten marraskuun 2024. MCP on nyt yli 400M kuukausittaista SDK-latausta (4× kasvu vuodessa).
- **Kriittinen korjaus – Remote MCP -uudelleenyhteys**: Remote MCP-palvelimet non-interactive (`-p`) ja SDK-istunnoissa eivät enää jää pysyvästi irti yhteyden katketessa. Palvelimet yhdistävät automaattisesti uudelleen tai raportoivat epäonnistuneina. Ennen korjausta katkennut yhteys vaati manuaalisen uudelleenkäynnistyksen.
- **Hallitut agentit**: mallimääritys ja vaivatasot lisätty `/tasks`- ja agenttinäkymiin; sessiobudjetti, neuvoja-malli, inference geo pinning Claude Managed Agentsissa.
- **Admin API GA**: Claude Enterprise -käyttäjänhallinta (jäsenet, kutsut, ryhmät, roolit) API:n kautta nyt yleisessä saatavuudessa.

*Miksi tärkeä / mitä kokeilla:* Remote MCP -uudelleenyhteys on välitön päivitys tuotantoagenttijärjestelmille. Geo pinning on kriittinen EU-datan residenssivaatimusten kannalta. Päivitä Claude Code välittömästi jos ajat `-p`-modin agentteja tai SDK-pohjaisia työnkulkuja.

## Syväluentaehdokkaat

1. **arXiv: VoiceMem – Streaming Dual-Brain Memory for Real-Time Interaction (2608.26005, 26.8.2026)** – Tärkein uusi arkkitehtuuripaperi tällä viikolla jos rakennat tai käytät puhepohjaisia agenttijärjestelmiä. Artikkeli ratkaisee käytännönläheisesti ongelman joka on este tuotantotason puhekäyttöliittymille: kuinka antaa mallille sekä tarkka faktamuisti (asiakashistoria, sopimustiedot) että emotionaalinen konteksti (viime kerran tunnelma) ilman havaittavaa latenssia. Lue erityisesti Section 3 (dual-brain arkkitehtuuri) ja Section 5 (latenssi- ja tarkkuusvertailut) – numeroita voi käyttää suoraan vertailupohjana jos suunnittelet oman muistijärjestelmän SLM-pohjaiseen tuotteeseen. Kaksi avointa kysymystä joita kannattaa harkita lukiessa: (a) miten dual-brain skaalautuu erittäin pitkissä multi-session-työnkuluissa, ja (b) sopiiko sama rakenne tekstipohjaisiin chatbotteihin. [arxiv.org/abs/2608.26005](https://arxiv.org/abs/2608.26005)
