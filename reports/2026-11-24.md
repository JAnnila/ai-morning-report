## Kehitystyökalut ja agentit

**Claude Ship: `/ship`, PR Steward ja Claude Approvals** (julkaistu 23.11.) `[Kokeile]` - Anthropicin uusi kokonaisuus vie PR:n katselmoinnista korjauksiin ja hyväksyntäpäätökseen asti. Siinä on kolme osaa:
- **Code Review** (GA) katselmoi PR:n koko koodikantaa vasten. Katselmointitason (Quick, Standard tai Deep) voi valita repokohtaisesti.
- **PR Steward** (beta) korjaa failaavan CI:n, merge-konfliktit ja katselmointipalautteen. Jokaisen pushin jälkeen se kommentoi, mitä muutti ja miten muutoksen voi perua. Sitä ohjataan `@claude`-maininnalla ja pysäytetään komennolla `@claude stop`. PR Steward ei itse hyväksy eikä mergeä.
- **Claude Approvals** (beta) hyväksyy rutiinimuutokset repon oletushaarassa olevan policy-tiedoston perusteella ja ohjaa arkaluontoiset muutokset ihmiselle.

Saatavuus ja hinta: toimii vain GitHub-repoissa Team- ja Enterprise-planeilla. Ei saatavilla organisaatioille, joilla on ZDR, HIPAA-konfiguraatio tai asiakkaan hallinnoimat salausavaimet. Laskutus perustuu tokeneihin, ja `/ship` lasketaan tavalliseksi Claude Code -käytöksi. `/ship` tulee käyttöön Claude Codeen ja desktop-sovellukseen vaiheittain 23.11. alkaen. [Claude](https://claude.com/resources/articles/introducing-claude-ship) · [The New Stack](https://thenewstack.io/anthropic-claude-ship-approvals/)
*Miksi tärkeä / mitä kokeilla:* Azure Repos ei ole tuettu, joten tämä koskee vain mahdollisia GitHub-repojanne. Siellä voitte ajaa `claude update` ja kokeilla `/ship`-komentoa valmiiseen muutokseen. Ottakaa Claude Approvals käyttöön ensin observe-tilassa ja asettakaa spend limit Code Review'lle ja PR Stewardille ennen kuin otatte ne käyttöön.

**Agentic Autofix for GitHub Advanced Security for Azure DevOps** (public preview, julkaistu 23.11.) `[Kokeile]` - Copilot Autofix toimii nyt Azure DevOpsissa Copilot coding agentin päällä. Se tutkii repon kontekstia, voi tehdä usean tiedoston korjauksen ja avaa siitä PR:n. Uutta on tuki riippuvuushaavoittuvuuksille ja kolmansien osapuolten skannereiden hälytyksille. Autofix ei koskaan mergeä itse, eikä sen käyttöönotto käynnistä skannauksia tai korjauksia automaattisesti. Sen voi ottaa käyttöön organisaation, projektin tai repon tasolla. Korjausten luonti laskutetaan organisaatioon linkitetyltä Azure-tilaukselta. Vaatimuksena on GHAS for Azure DevOps tai GitHub Code Security for Azure DevOps ja konfiguroitu koodiskannaus. [Azure DevOps Blog](https://devblogs.microsoft.com/devops/agentic-autofix-for-advanced-security-for-azure-devops-public-preview/) · [Sprint 280 -julkaisutiedot](https://learn.microsoft.com/en-us/azure/devops/release-notes/2026/sprint-280-update)
*Miksi tärkeä / mitä kokeilla:* Tämä on ensimmäinen agenttipohjainen korjaaja suoraan Azure Reposissa. Ottakaa se käyttöön yhdessä .NET-repossa, jossa CodeQL on päällä, pyytäkää korjaus muutamaan NuGet-riippuvuushälytykseen ja verratkaa tulosta siihen, mitä Claude Code tekisi samalle hälytykselle.

## Toimintatavat ja arkkitehtuuripatternit

**Hyväksyntäpolicy koodina, ensin observe-tilassa** (dokumentoitu 23.11.) `[Kokeile]` - Claude Shipin dokumentaatio kuvaa vaiheittaisen tavan antaa agentille hyväksyntäoikeus:
1. Hyväksyntäsäännöt kirjoitetaan tiedostoksi repon oletushaaraan, jolloin niitä katselmoidaan ja versioidaan kuten koodia.
2. Ensin policy ajetaan observe-tilassa, joka näyttää, mitkä PR:t agentti olisi hyväksynyt.
3. Vasta kun osumat on todettu oikeiksi, agentin hyväksyntä lisätään branch protectionin pakolliseksi tarkistukseksi. Arkaluontoiset polut ohjataan aina ihmiselle.

Malli on yleinen eikä riipu Claude Shipistä. [Claude](https://claude.com/resources/articles/introducing-claude-ship) · [DEV: policy file decides what merges](https://dev.to/ton_thnhthy_ba110cce85/claude-ship-is-here-anthropics-agents-now-review-fix-and-approve-your-prs-and-the-policy-file-4ci7)
*Miksi tärkeä / mitä kokeilla:* Saman voi tehdä Azure DevOpsissa: agentti (esim. Claude Code -katselmointi pipelinessa) jättää PR:ään "would approve" -statuksen ei-pakollisena status checkinä. Kahden viikon jälkeen verratkaa sitä ihmisten päätöksiin ennen kuin muutatte sen pakolliseksi branch policyksi.

**Tokenikustannusten seuranta OpenTelemetryn `gen_ai`-attribuuteilla** (Claude Code 2.1.331, 23.11.) `[Kokeile]` - Claude Code kirjaa nyt jokaiseen mallikutsun spaniin OpenTelemetryn GenAI-semanttisten konventioiden mukaiset `gen_ai.usage.*`-, `gen_ai.response.model`- ja `gen_ai.operation.name`-attribuutit. Samat attribuutit ovat käytössä muissakin GenAI-instrumentoinneissa (esim. Microsoft Agent Framework ja Semantic Kernel), joten Claude Coden ja omien .NET-agenttien kulut voi koota samaan näkymään ilman erillistä parseria. [CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)
*Miksi tärkeä / mitä kokeilla:* Asettakaa `CLAUDE_CODE_ENABLE_TELEMETRY=1` ja OTLP-exporter Azure Monitoriin tai Application Insightsiin. Tehkää KQL-kysely, joka summaa `gen_ai.usage.input_tokens`- ja `output_tokens`-arvot mallin ja käyttäjän mukaan. Huomatkaa, että syötetokeneihin sisältyvät myös cache-tokenit.

## Tietoturvavahti

**OX Security: suuri osa MCP-palvelimista ajaa koodia, jota ei voi varmentaa** (julkaistu 23.11.) `[Tiedoksi]` - OX analysoi 542 207 komponenttia npm:stä, PyPI:stä, MCP-palvelimista ja Agent Skilleistä. 834 liputetusta MCP-palvelimesta 67 % toimi julkaisijan hallitsemalla infrastruktuurilla, jossa ajossa olevaa koodia ei voi verrata julkaistuun lähdekoodiin. Agentti siis "ottaa käskyjä tuntemattomilta". Luvut ovat yhden toimittajan omasta tiedotteesta, eikä alkuperäistä raporttia löytynyt hauilla. [PR Newswire](https://www.prnewswire.com/news-releases/ai-agents-are-taking-orders-from-strangers-ox-security-research-finds-302948335.html)
*Miksi tärkeä / mitä kokeilla:* Tämä vahvistaa aiemmissa raporteissa kuvatun linjan: suosikaa MCP-palvelimia, joiden koodi ajetaan omassa ympäristössä kiinnitetyllä versiolla (ei `@latest`). Etäpalvelimille määritelkää `allowedMcpServers`-lista hallittuihin asetuksiin.

**AI:n löytämä Ghostscript-haavoittuvuus CVE-2026-125396** (CSA:n katsaus 23.11.) `[Tiedoksi]` - Cloud Security Alliancen 23.11. CISO-katsauksen mukaan AI:n avulla löydetty Ghostscriptin sandbox-pako on hyödynnettävissä palvelimilla tavallisten upload- ja esikatselutoimintojen kautta. Korjaus julkaistiin syyskuussa, mutta isot jakelut ovat yhä jäljessä. [CSA CISO Daily Briefing](https://labs.cloudsecurityalliance.org/research/alt-ciso-briefing-2026-11-23/)
*Miksi tärkeä / mitä kokeilla:* Tarkistakaa, ajavatko tiimin PDF- tai kuvaesikatselua tekevät palvelut tai konttikuvat (esim. Linux-pohjaiset App Service -kontit) Ghostscriptiä. Jos ajavat, päivittäkää base image.

Muuta: OpenAI ja Cisco julkaisivat 23.11. Shirudon, avoimen eBPF-pohjaisen Linux-ajoympäristön, joka suojaa käynnissä olevia järjestelmiä korjausten käyttöönoton ajan ([OpenAI](https://openai.com/index/introducing-shirudo/)). Projekti on varhaisessa vaiheessa. Claude Code 2.1.331 korjasi `PermissionDenied`-hookin `retry: true` -käytöksen: Claude yrittää estettyä kutsua uudelleen vain, jos hook pyysi juuri sitä kutsua.
