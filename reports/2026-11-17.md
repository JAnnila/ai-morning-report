# AI-aamuraportti - 2026-11-17

## Päivän tärkeimmät

- Claude Code 2.1.326 (16.11.) toimii nyt Code Modessa myös silloin, kun agent teams on päällä. Lisäksi se varoittaa käynnistyksessä puutteellisista `--allowedTools`-, `--disallowedTools`- ja `--tools`-säännöistä, mikä kannattaa tarkistaa CI-putkista.
- Sama julkaisu korjasi useita luottamus- ja lupamallin virheitä. Niistä tärkeimmät: Up+Enter hyväksyi kansion luottamuskyselyn huomaamatta, tiedostoja poistavat Bash-komennot näkyivät transkriptissa hakuina tai lukuina, ja lupasäännöt näyttivät tallentuneen, vaikka asetustiedostoon ei voitu kirjoittaa.
- Kontekstin tiivistys korjattiin Bedrockissa, Vertexissä ja Foundryssa: se saattoi vastata käyttäjän viestiin yhteenvedon sijaan. Azure AI Foundryn kautta Claude Codea käyttävien kannattaa päivittää.
- Alibaban Qwen4-Max on mediatietojen mukaan siirtynyt previewstä yleiseen saatavuuteen (15.–16.11.). Hinta on $1,50 / $4,50 per miljoona tokenia, konteksti 1M, eikä avoimia painoja ole.

- Bash-työkalun `grep` ei enää ohita joitakin tekstitiedostoja hiljaa.

**Claude Code 2.1.326: MCP-, plugin- ja mod-muutokset** (julkaistu 16.11.) `[Kokeile]` - Muutokset:
- Jos ylläpitäjä lisää `managed-mcp.json`-tiedoston kesken session, Claude Code kertoo nyt, miksi MCP-palvelimet lakkaavat latautumasta.
- Epäonnistunut tai luottamattomassa kansiossa ajamatta jäänyt MCP `headersHelper` sai aiemmin muut sessiot käynnistymään ilman kyseistä palvelinta. Tämä on korjattu.

- Modeihin tuli `overflowX="scroll"` (`Box`) sekä `maxLines` ja `wrap="clip"` (`Text`).

## Tietoturvavahti

**Claude Code 2.1.326: luottamus- ja lupamallin korjaukset** (julkaistu 16.11.) `[Kokeile]` - Julkaisussa ei ole erillistä tietoturvaosiota, mutta useat korjaukset koskevat luottamusrajaa:
- Up+Enter vastasi "Yes" kansion luottamuskyselyyn, kun kysely näytettiin jo luotetun yläkansion alla.
- Tiedostoja poistavat tai ylikirjoittavat Bash-komennot (`find -delete`, `cat a > b`, `sort -o`) näkyivät transkriptissa hakuna tai lukuna.
- `/permissions`-näkymässä tai lupakyselyssä lisätyt säännöt näyttivät tallentuneilta, vaikka asetustiedostoon ei voitu kirjoittaa. Nyt terminaali varoittaa ja nimeää tiedoston.
- Kesken session virheellisesti tallennettu asetustiedosto ohitettiin hiljaa, ja tuhansia tasoja syvälle sisäkkäiset arvot saattoivat kaataa ohjelman tai soveltua vain osittain. Nyt yli 64 tason arvot pudotetaan varoituksen kera.
- Hallittujen asetusten PreToolUse-hookit eivät jättäneet torjumistaan kutsuista OpenTelemetry-`tool_decision`-tapahtumaa eivätkä `permission_denials`-merkintää.
- Taustapalvelu saattoi lopettaa käyttäjän omia prosesseja, kuten SSH-kirjautumisen, kun prosessinumero oli kierrätetty.
- `claude purge` piilotti kysymyksensä, kun stdout oli uudelleenohjattu, jolloin yksi näkymätön Enter saattoi poistaa projektin datan.

[CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)
*Miksi tärkeä / mitä kokeilla:* Päivittäkää kaikki koneet versioon 2.1.326. Jos keräätte hallittujen hookien torjunnat OpenTelemetryyn, tarkistakaa 16.11. jälkeen, että `permission_denials` alkaa täyttyä, sillä aiemmat lokit ovat olleet vajaita.

Muuta: Uusia CVE:itä agenttien, MCP:n tai kehitystyökalujen osalta ei löytynyt ikkunasta. Copilot CVE-2026-103572, MCPhantom ja keyv-mato on käsitelty aiemmin.

## Syväluentaehdokkaat

- **Code Mode ja agent teams yhdessä:** 2.1.326:sta alkaen MCP-raskaat työkalukutsut voi ajaa skriptinä myös rinnakkaisissa tiimeissä. Mitatkaa yhdellä monikerroksisella tehtävällä (.NET + Angular + Azure DevOps -MCP), paljonko token-kulutus ja kesto muuttuvat, ennen kuin otatte yhdistelmän oletukseksi.
- **Hallittujen asetusten ja lupasääntöjen auditointi:** Uusi `/status`-rivi, `--allowedTools`-varoitukset, tallentumattomien sääntöjen varoitus ja korjattu OTel-kirjaus tekevät nyt näkyväksi sen, mikä aiemmin epäonnistui hiljaa. Käykää CI:n ja kehittäjäkoneiden konfiguraatiot läpi kerralla 2.1.326:lla ja kirjatkaa, mitkä säännöt eivät oikeasti olleet voimassa.
